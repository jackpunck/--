# 循序 · AI 健身助手

根据 [AI 健身助手功能实现文档](AI健身助手功能实现文档.md) 实现的响应式网页应用。电脑和手机连接同一服务，使用同一账号同步数据。

## 比赛目标与当前范围

本项目用于参加**软件设计赛**。预期将服务部署到 **2 核 CPU、4 GB 内存的服务器**，后续提供网页、Windows EXE 和 Android APK 三种访问入口。各入口连接同一服务器，同一账号共享资料与记录。

服务器负责业务计算、账号、数据同步和 AI 请求转发；用户设备承担视频解码、姿态推理、角度测量及 3D 渲染，AI 供应商负责动作点评等生成式任务。

**当前继续开发和完善网页项目，暂不进行 EXE、APK 打包或客户端改造。** 桌面端和手机端属于后续交付目标，尚未实现或验收。后续开发应保持这一计算分工，并为客户端复用网页与服务接口保留条件。详细约定见 [部署与接口](docs/部署与接口.md#比赛交付目标与实施范围)。

## 启动

需要 **Node.js 24 或更高版本**，主应用没有需要安装的第三方运行依赖。

```powershell
npm start
```

打开 **http://localhost:3000**，未登录时先展示可滚动的产品介绍页；顶部展示环形横幅，下方提供登录／注册表单，导航「登录账号」可直接定位到表单。创建账号并填写五项基本资料。日常训练、饮食记录和动作查阅可直接使用。

更新项目后，在已打开的浏览器页面刷新一次。若曾使用旧版缓存，在 Edge 按 `Ctrl+Shift+R` 强制刷新即可，不必清除站点数据。主应用与3D资源现使用重新验证缓存策略；离线页面仍由 Service Worker 提供。

AI 对话、图片餐食识别、AI 规划和动作点评需要先进入「个人设置 → AI 服务」：选择供应商、填入 API Key、点击「获取模型」，勾选常用模型并保存。已提供 **12 家供应商预设**，地址与协议自动填写；同一家供应商可启用多个模型，再为四个任务分别选择。其他服务或本地模型可使用「自定义供应商」。详见 [AI 供应商](docs/AI供应商.md)。

同一局域网的手机可访问 `http://电脑的局域网IP:3000`。手机安装和离线重载需要 HTTPS；正式跨网络使用请部署到共同可访问的 HTTPS 地址。详见 [部署与接口](docs/部署与接口.md)。

## 计算分工与服务器配置

当前按 **2 核 CPU、4 GB 内存服务器，小规模上线** 设计：

| 位置 | 执行内容 |
| --- | --- |
| 用户浏览器 | 视频解码、MediaPipe 姿态推理、人物跟踪、角度测量、关键帧提取；视频播放、3D 渲染和界面交互 |
| 项目服务器 | 营养目标、摄入合计、食物份量与热量换算、RM 换算、食谱及替换、训练计划生成与排期、繁忙日顺延、训练完成核验、成就及阶段统计；账号、数据库、同步和 AI 请求转发 |
| 用户配置的 AI 供应商 | 对话生成、餐食识别、规划建议、动作点评 |

视频分析使用每位用户自己设备的 CPU/GPU，无需安装程序，原视频保留在浏览器。服务器不运行视频推理模型，也无需 GPU 或 Python。业务计算通过鉴权后的 `POST /api/compute` 返回结果；断开服务时不会在浏览器重新计算，已有记录仍保存在缓存中。

动作评估默认使用 **高精度（MediaPipe Heavy）**，可切换 **标准（Full）**。Heavy 的模型文件约 31 MB，首次使用从本项目服务器下载并按需缓存，分析速度和内存占用取决于用户设备。两种模式均保留每秒 15 帧采样；切换后需重新评估。模型升级主要针对骨骼关键点，动作名称和标准程度仍由配置的 AI 根据完整数据判断，具体准确率需要带标注的视频验证。

模式验证：`npm run qa:motion` 对比两种模式的真实视频分析与界面切换；`npm run qa:motion:models` 检查 CPU 回退、兼容解码、软件解码与 AI 数据中的模型版本。均使用隔离测试数据，不调用收费 AI。

2 核 4 GB 可作为 1–2 人同时使用视频分析的小规模部署起点，实际容量需要在目标服务器上测试。建议准备 40–60 GB SSD、至少 5–10 Mbps 公网带宽，并使用域名和 HTTPS。手机和低性能电脑的视频分析速度取决于其硬件与浏览器。详细配置见 [部署与接口](docs/部署与接口.md)。

## 已实现的主要流程

- **视频动作评估（试验版）**：本机一次提取完整骨架、逐帧客观角度和数据质量信息，AI 结合最多 6 张关键画面，判断「动作基本标准」「动作需要调整」或「暂时无法判断」，给出最多 3 条重点建议。本地不再分类、计次或评分，也不在 AI 返回后重新分析。完整数据能放入一包时只调用一次模型，长数据完整分批审阅后汇总；支持进度显示、超时重试和取消。新报告只保存 AI 结论、建议与身份和质量等元信息，可跨设备同步；原视频、完整骨架和逐帧测量不保存。历史记录保持原样，在简化界面中阅读。更新后需刷新页面，旧摘要接口不再受理。范围与验证边界见 [视频动作评估](docs/视频动作评估.md)。
- **手机视频直读**：支持常见 MP4、MOV 等视频；浏览器无法直接读取时，使用本地软件解码器处理 HEVC、HDR、竖屏旋转和 4K，逐帧分析，不生成中间 MP4。选片只读取信息与首帧，分析后可回看采样画面，AI 关键图片从原片提取。原视频不改写、不上传。单段仍限制 120 秒、200 MB，耗时取决于设备。
- **个人空间**：注册登录、首次建档、带日期的阶段历史、阶段趋势和数据导出/删除。
- **AI 对话**：Markdown 排版、逐步显示回复、停止与重新生成、复制消息和图片、图片/文件粘贴与拖入、附件预览和上传重试、会话历史与连续追问。向上阅读不抢滚动，随时回到最新回复。你明确要求时，AI 可在对话中增删改训练计划、日程任务和今日饮食，并显示实际操作结果。
- **训练日程**：按周、按日期展示训练任务；支持新增、编辑、删除和跨日期拖动。二至五分化循环草案、实际训练和力量估算继续保留。AI 按训练循环分配日期，保留过去和已完成的训练快照。详见 [训练日程](docs/训练日程.md)。
- **饮食**：根据当天是否有训练任务自动切换训练日/休息日及营养目标，拖动改期后同步更新；拍照/文字估餐、餐前餐后及标签修订、手动份量与营养值、确认入账、补记与删除、单餐/多日食谱、食物替换与实测生熟换算。
- **知识大全**：代谢与每日消耗估算、三大营养素热量换算、12 种可调整的常见食物份量；输入单组重量与次数估算 1RM 最大重量，在输入卡片中换算目标 RM，点击 Epley、Brzycki 卡片切换公式并查看 1–15RM 换算表；25 个动作的搜索与 3D，包含 24 个往复动作和持续等长的平板支撑；肌肉图谱支持点选名称及高亮。对话按所问肌肉或动作显示对应 3D 卡片。详见 [知识大全](docs/知识大全.md)。
- **同步**：SQLite 持久化、每账号 IndexedDB 离线队列、自动重连同步、记录版本检查及双方冲突选择。图片保存在账号所属服务中；上传和 AI 请求需要网络。

## 验证

```powershell
npm test
npm run check
```

业务计算与浏览器分工验证：`npm run qa:compute`。覆盖餐食份量和热量计算、连续修改输入、繁忙日顺延、营养目标切换、服务断连和页面切换；使用临时账号、数据库及模拟 AI，不读取已有账号。浏览器依赖见 [浏览器验证](docs/浏览器验证.md)。

测试使用临时数据库和本地模拟 AI 上游，不需要真实密钥。覆盖领域计算、真实 HTTP/SQLite、用户隔离、附件授权、密钥隐藏、删除、同步竞争、模型发现与任务选模，以及三种 AI 协议和餐食识别协议。模拟服务测试验证请求和数据流程，真实供应商的生成质量、视觉识别精度需要使用自己的服务实测。

登录展示页使用浅灰紫底色与电蓝强调，页面顶部为环形横幅与开始记录入口，下方排列简短介绍、登录注册与双列功能卡片。图片高度为 300px，标题与文案采用紧凑排版。图片到达视口高度约 82% 的位置时，自动播放 1.3 秒的放大、旋转和回弹；停止滚动后继续播完，向上离开触发点时反向收起。文字渐变显现，环形框架独立连续旋转。暂停动效与系统减少动态时完整展示内容，登录后清理展示页动效。字体与 GSAP 均本地提供并纳入离线缓存。验证脚本：`node scripts/qa-landing.mjs`；浏览器实测详见 [浏览器验证](docs/浏览器验证.md)。

对话专项浏览器验证：`node scripts/qa-chat.mjs`。覆盖 Markdown、流式显示与停止、通过对话实际增删改计划、历史训练保留、输入框及手机布局；浏览器环境要求见 [浏览器验证](docs/浏览器验证.md)。使用方式和接口约定见 [AI 对话](docs/AI对话.md)。

知识大全与对话 3D 验证：`node scripts/qa-knowledge.mjs`。
RM 与最大重量估算、桌面/手机布局验证：`node scripts/qa-weight-conversion.mjs`。

日程与今日饮食 AI 操作验证：`node scripts/qa-calendar.mjs`。

剪贴板与交互验证：`node scripts/qa-composer.mjs`，使用独立浏览器内的测试剪贴板，不读取个人系统剪贴板。

模型独立检查与重新构建：

```powershell
cd 精细模型与动作开发
npm install
npm test
npm run build
```

预构建的模型已随项目保留，主应用运行不要求重新构建它。修改动作目录后，在根目录执行 `npm run sync:models`，将能力清单同步到应用与 AI 提示。网页采用独立二进制网格和后台解码；双击模型目录的 `index.html` 会自动使用包含全部资产的离线包。

## 本地动作视频测试集

视频保存在 `测试集/`，按动作和标签分文件夹保存。原始来源、作者、许可证与标签依据见文件夹内的 `manifest.json`。作者正误标注、未标注正误的演示和正误混合教学分别保存。

下载清单为 `scripts/motion-test-dataset.json`。继续下载剩余文件：

```powershell
node scripts/download-motion-videos.mjs
```

下载器将整个文件夹限制在 3,000,000,000 字节以内，保留已有文件。按最新要求，剩余视频直接下载原文件，不再转码或检查媒体；此前已转换的文件保持原样，具体处理方式记录在清单内。视频文件夹已排除版本控制。

## 项目结构

| 路径 | 作用 |
| --- | --- |
| `public/` | 响应式界面、浏览器视频分析、IndexedDB 同步、离线应用壳；保留供服务器与测试复用的纯函数模块 |

| `tests/` | 自动化领域、契约、后端和同步测试 |

`.gitignore` 已排除本地数据与数据库、密钥和 `.env.*`、依赖、运行日志、浏览器测试产物及开发缓存；保留 `.env.example`、代码、文档、Excel 原始资料和运行必需的 3D 预构建资源。

## 实现边界与资料

- 营养目标是普通成年人的起始估算，内置食物值标注为近似值，包装食品可手动覆盖为标签值。具体公式与 Excel 取舍见 [算法来源](docs/算法来源.md)。
- 三、四分化与对应变式参考原 Excel；二、五分化为应用扩展。完整 Excel 文件保持原样，没有在浏览器内重建整份工作簿。
- 支持 OpenAI 兼容 Chat Completions、Anthropic Messages 和 Gemini GenerateContent 三种协议。图片/PDF 会转换为所选协议的附件格式，实际支持取决于模型；TXT/Markdown/CSV/JSON 作为文本上下文。模型图片能力来自供应商返回字段，缺少信息时显示“待确认”。
- 内置 5 条已核对来源的知识卡片；当前动作与知识资料尚未获得运动或医疗专业人士审核。审核状态和后续维护方法见 [知识维护](docs/知识维护.md)。
- 精细模型包含 700 个结构、854,514 个三角面和 46 根控制骨骼；25 个动作均有教学演示，手机性能取决于 GPU。动作轨迹、蒙皮和发力颜色属于教学近似，未替代专业动作审核。模型许可与署名保持在原目录，按原 CC BY-SA 要求使用。
- [功能验收清单](docs/功能验收.md) 列出各项能力、验证方式及边界；[动作接入](docs/动作接入.md) 说明 iframe 和新增动作接口。
- [浏览器验证](docs/浏览器验证.md) 记录桌面、手机布局、离线重载、双端冲突、餐食修订和历史训练测试。

原 `cherry-studio` 仅作为交互和供应商配置参考，没有复制其代码。
