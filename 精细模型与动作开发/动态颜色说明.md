# 统一的动作发力示意

当前功能用于帮助用户观察一个动作中哪些肌肉参与、什么时候相对更用力、什么时候相对较轻。曲线是人工整理的教学近似，**不是实测肌力、肌电激活率或人体极限百分比**。

## 颜色规则

对同一动作、同一块肌群，先取得完整行程曲线的最小值与最大值：

```text
相对强度 = (当前示意值 - 全程最小值) / (全程最大值 - 全程最小值)
```

- 最低值为 0%，浅色；最高值为 100%，深色；中间按比例变化。
- 比较范围固定为整段动作，不随播放到哪一帧重新归一化。
- 每块肌肉分别归一化。不同肌肉都达到 100%，只代表各自处于本程示意峰值，不能比较真实力量大小。
- 浅色表示本程相对较轻，不表示完全不发力。下降控制、底部转向、持重暂停也可能需要持续用力。
- 恒定曲线采用稳定的中间色，界面显示“持续稳定”或“持续用力”，不显示容易误读的百分比，也不计算除以零。全零曲线保持最低色。
- 未配置的肌肉保留中性材质；图谱继续使用解剖高亮。

界面不再提供牛顿值、参考体重或负重求解入口。统一示意模型没有肌力平衡约束求解，因此当前 25 个动作不会再因旧仿真中的“无解”而中断颜色。

## 当前动作

已覆盖目录中全部 25 个动作：24 个往复动作及 1 个持续等长支撑。

| 动作 | 示意趋势 | 持续稳定 |
| --- | --- | --- |
| 深蹲 | 股四头肌、臀肌在较深位置及起身初段较强，接近站直时较轻 | 核心 |
| 俯卧撑 | 胸部、肱三头肌和三角肌在较低位置及推起前半段较强，高位相对较轻 | 核心 |
| 哑铃弯举 | 肱二头肌在前臂接近水平时较强，继续弯到顶端后略减轻 | 握持肌群、核心 |

新增动作的配置位于 `extended-activity-profiles.js`，轨迹位于 `motion-poses.js`：

| 动作 | 教学观察重点 |
| --- | --- |
| 哑铃卧推、上斜哑铃卧推 | 较低位置及开始推起时颜色较深 |
| 器械推胸、高位下拉、辅助引体向上 | 用中段加深提示推拉中的主要参与肌群 |
| 坐姿划船、单臂哑铃划船 | 背部在收回区间加深，屈肘肌群在中段加深 |
| 哑铃推举 | 肩部在推起前中段较强，顶部相对减轻 |
| 侧平举、俯身飞鸟 | 抬起、展开时逐渐加深 |
| 绳索下压、过顶臂屈伸、锤式弯举 | 屈伸中段加深，控制还原仍参与 |
| 高脚杯深蹲、罗马尼亚硬拉、反向弓步 | 下放较深及起身初段较强 |
| 腿弯举、腿屈伸 | 用中段或伸展区间加深提示目标肌群；实际阻力取决于器械 |
| 臀桥、卷腹、提踵 | 抬起时逐渐加深，回落时逐渐变浅 |
| 平板支撑 | 稳定姿态和中间色，不随播放进度虚构周期峰值 |

卷腹和平板支撑的主要腹部肌群使用透视覆盖高亮，颜色仍按同一曲线计算，界面明确说明；覆盖层共享原几何与骨架，复用材质，不在每帧创建网格。

单臂划船动画示范右臂，双侧肌群着色用于位置对照；此版本不计算左右侧独立力量。器械为简化轮廓，颜色曲线不模拟不同器械的凸轮、摩擦或助力曲线。

这些是当前教学轨迹的简化设置，不能推广成所有变式、负重和个体的精确发力结论。动作要领参考 [ACE 俯卧撑](https://www.acefitness.org/resources/everyone/exercise-library/41/push-up/) 和 [ACE 深蹲](https://www.acefitness.org/resources/everyone/exercise-library/135/bodyweight-squat/)；曲线关键点的数值是本项目的人工示意参数，不是从这些来源提取的实验数据。

## 统一实现

| 文件 | 职责 |
| --- | --- |
| `activity-profiles.js`、`extended-activity-profiles.js` | 每个动作的参与肌群、主辅角色、曲线关键点、较强／较轻位置及阶段说明 |
| `muscle-activity.js` | 统一校验、完整行程范围计算、平滑插值及归一化 |
| `motion-timeline.js` | 输出动作姿态进度和阶段，供骨架与颜色共同使用 |
| `atlas-model.js` | 将相对强度映射为浅到深的材质颜色，复用现有网格与材质 |
| `src.js` | 显示阶段提示、相对百分比及稳定肌群说明 |

关键点之间使用不会超出端点范围的 smoothstep 插值，避免插值产生假的峰值。当前往返行程使用同一姿态曲线，阶段说明区分举起、控制还原和保持；播放速度只改变播放快慢。没有把播放速度、暂停或方向转换当作肌肉发力大小。

## 后续动作如何接入

新增 3D 动画仍需制作或导入动作轨迹，并在动作目录注册。发力示意只需增加配置，统一计算器和材质系统不需要按动作重写，也不需要制作新的解剖人体或运行 OpenSim。

1. 让动画输出标准姿态进度 `q`：起始为 0，行程另一端为 1。
2. 在 `activity-profiles.js` 或 `extended-activity-profiles.js` 添加同名配置，使用已有的真实肌群 ID。
3. 为每个参与肌群填写 `curve`，以及 `role`、`peak`、`low`；为各阶段填写说明。
4. 核对最浅／最深颜色与动作位置一致，确认稳定肌群、还原阶段和转向提示合理。

配置结构示例：

```js
newExercise: {
  firstContraction: 'concentric', // 首段是向心还是离心
  note: '这个动作的主要观察点',
  phases: {
    hold: '起始保持的说明',
    concentric: '发力阶段的说明',
    turn: '转向时的说明',
    eccentric: '控制还原的说明',
  },
  muscles: {
    biceps: {
      role: 'primary', // primary / secondary / stabilizer
      curve: [[0, 10], [0.5, 30], [1, 20]],
      peak: '行程中段', low: '起始位置',
    },
    core: {
      role: 'stabilizer', curve: [[0, 1], [1, 1]],
      peak: '全程稳定躯干', low: '持续支撑',
    },
  },
}
```

`curve` 是 `[姿态进度, 示意值]` 的有序数组；必须覆盖 0 和 1，进度严格递增，值为非负有限数。数值单位任意，整体等比例放大或加上相同基线，都不改变归一化颜色。示例中的动作和数值仅展示配置格式，需要按实际新动作审核。

## 构建与检查

在本目录运行：

```powershell
npm run build
npm test
```

检查涵盖新增动作配置、整程最小／最大值、尺度变化不影响颜色、3003 个播放采样点的连续性、动作峰值、稳定肌群、暂停同步及 GPU 资源复用。主项目的 `scripts/qa-activity.mjs` 验证 Edge 中的真实着色、逐段拖动、倍速、隐藏查看器、静态图谱、手机布局及聊天卡片的示意标记。

原来的 `muscle-force.js`、OpenSim 模型、力表和离线生成脚本保留供研究参考，当前网页不导入它们。其验证命令为 `npm run test:force`，原方法与许可见 [历史肌力仿真说明](历史肌力仿真说明.md)。原模型文件与许可均保留；教学曲线未从旧肌力表生成。
