# 指定负重下的肌力估算

当前颜色对应参考人体模型计算出的肌肉拉力，单位为牛顿（N）。这是**简化准静态仿真估算**，尚未用真人实验验证；数值计算残差不能解释为人体肌力预测误差。

## 使用方式

打开深蹲、哑铃弯举或俯卧撑详情，在“肌力仿真”输入负重。

| 动作 | 负重含义 | 当前范围 | 参考模型 |
| --- | --- | --- | --- |
| 深蹲 | 肩部附加总重 | 0–60 kg | Gait2392，下肢矢状面 |
| 弯举 | 每只哑铃的质量 | 0–20 kg，默认 5 kg | MoBL-ARMS，肩与肘 |
| 俯卧撑 | 躯干附加总重 | 0–30 kg | MoBL-ARMS，肩与肘；全身静力支撑估算 |

参考全身质量约 75.2 kg。未提供自定义体型或个体肌力校准。两侧假设对称，界面报告**单侧**已建模肌肉的拉力标量之和，并将该数值镜像着色到两侧肌群。它不是肌群净合力，也不是负重本身的重力。显示模型包含一个肌群的多个结构，颜色是肌群汇总值，不能读成单个肌束的独立拉力。

颜色使用固定 0–3000 N 色标。内部色阶为 `sqrt(min(F/3000,1))`，用于保留低力区域的可见差异；超过上限保持红色，但数值不截断。不按每个动作、每帧的最大值重新缩放。相同力得到相同颜色，主辅角色、被选中状态和向心／离心标签不改变肌力色阶。核心等未建模部位保持中性颜色；中性颜色不能解读为真实肌肉没有发力。

## 力的计算

1. 从现有显示骨架导出姿态及实际躯干旋转。深蹲和弯举各 101 个姿态，俯卧撑 117 个姿态，在接近伸肘的起始区间加密采样。将深蹲关节角映射到 Gait2392；将上肢方向拟合到 MoBL-ARMS 的四个肩／肘坐标，腕和前臂旋转按动作固定。计算脚本直接使用导出的躯干角，不再另写一套动画公式。力表记录姿态数据的 SHA-256，测试会与实际显示骨架重新导出的姿态比对，防止动画修改后仍使用旧力表。
2. OpenSim 4.6 计算各姿态的肌肉力臂矩阵 `R(q)`；最大等长力 `Fmax` 直接来自参考模型。
3. 使用重力、指定负重和接触反力的虚功导数求关节所需力矩 `tau`，有限差分步长为 `1e-5 rad`。
4. 使用理想力执行器求解：最小化 `0.5 * sum(a²)`，约束为 `R(q) * Fmax * a = tau`、`0 ≤ a ≤ 1`。实际输出为 `F = Fmax * a`，没有将关节角直接当作肌力。SLSQP 未收敛时，再由独立的线性规划检查约束可行性；存在可行点则从该点重新优化。数值求解失败不会直接记作“无解”，而会中止生成并报告错误。
5. 各动作预计算 21 档负重，共 6699 个节点。网页先定位实际姿态采样区间，再做姿态／负重的双线性插值并检查力矩残差。OpenSim 与优化器不在网页内运行。

该形式属于 OpenSim 文档介绍的[静态优化与理想力执行器](https://opensimconfluence.atlassian.net/wiki/spaces/OpenSim/pages/53089619/How+Static+Optimization+Works)思路。实际求解由 Python 脚本调用 SciPy SLSQP 完成，不是直接运行完整 OpenSim Static Optimization Tool 管线。

### 接触与运动假设

- 深蹲：双脚对称承重，仅考虑垂直接触反力，压力中心采用当前总质心的水平投影；躯干使用原参考模型的刚体质量分布。髋、膝、踝三个矢状面坐标共同求解。
- 俯卧撑：躯干保持刚体支撑，根据分段质量与手脚位置求垂直手部反力；附加质量作用于躯干。由该反力与上肢重力求肩肘力矩。没有求解核心、腕部或肩胛稳定性的完整肌肉动力学。
- 弯举：上肢模型自重及哑铃重力作用于手部，拟合现有动画的上臂和前臂方向。
- 不计算惯性、加速度、疲劳、肌腱顺应性、被动组织力或力—长度—速度关系。最小平方激活也不能还原真实共同收缩。向心与离心在同一姿态／负重下采用相同准静态解；播放倍速仅供查看，不用于预测高速训练。
- 显示骨架与力学模型是不同资产，重定向并非完全一致。力表保留每个上肢姿态的方向分量误差、实际方向夹角误差和拟合后的关节坐标。生成过程拒绝未收敛或最大方向夹角误差超过 5° 的拟合结果。姿态贴合程度不能等同于肌力预测精度，仍未作人体实验校准。

## 超出范围与数值检查

原俯卧撑轨迹在最低点屈肘约 134°，超过当前上肢参考模型设置的约 130° 上限，且手腕与肘部位置造成过大的肘部力矩需求。现已调整手掌位置、肘部斜向展开方向及下降深度，最低点屈肘约 116°，手脚支撑点仍固定，骨段长度保持不变。动作设置参考 [ACE 俯卧撑说明](https://www.acefitness.org/resources/everyone/exercise-library/41/push-up/)；[手位影响肘部负荷的研究](https://pure.johnshopkins.edu/en/publications/hand-position-affects-elbow-joint-load-during-push-up-exercise)说明手位会影响关节负荷，但不能据此声称本项目数值已获实验验证。

不可行时保留姿态与动作说明，清除肌力数值和颜色，并说明“当前姿态与负重超出此模型的可解范围，不代表你无法完成动作”。肌肉最大力保持参考文件的原值；该提示属于当前简化模型的限制，不能解释为对用户真实能力的判断。

修复后的力表有 6498 个可行节点、201 个不可行节点。剩余不可行节点位于较大附加负重的俯卧撑，徒手及附加 5 kg 的整段动作均通过显示检查。新俯卧撑姿态的最大上肢方向拟合误差约 0.0201°；这只说明两套模型的肢段方向接近。

预计算可行解的保存前最大力矩残差记录在每个动作的 `validation` 中；力值保存到小数点后四位，自动测试要求保存后的残差小于 `0.02 Nm`。网页插值要求残差不超过 `max(0.1 Nm, 最大目标关节力矩的 1%)`，否则同样拒绝显示。这里的百分比是插值力矩残差阈值，**不是肌力预测精度为 1% 的声明**。

负重输入为空、负数或超范围时，不再显示上一次结果。暂停和拖动使用同一姿态数据；无效结果不会回退到以前的关节角示意色。

另选 8 个采样节点之间的实际动画姿态，直接用 OpenSim 重新计算力臂和外力矩，对照 0、5 kg 共 16 个插值结果，检查力矩残差。修复后这组检查的最大残差小于 0.05 Nm，并作为独立数值参考保存在 `scripts/fixtures/pushup-force-reference.json`。它比仅检查插值矩阵多一层验证，但仍属于数值检查，并非人体实测验证。

## 构建与验证

正常运行无需 Python，使用已构建的 `demo.bundle.js` 即可。重新生成数据，在模型目录运行：

```powershell
npm ci
node scripts/export-force-poses.mjs
python -m venv .venv
.venv/Scripts/python -m pip install -r scripts/force-requirements.txt
.venv/Scripts/python scripts/build-force-tables.py
.venv/Scripts/python scripts/build-force-reference.py
npm run build
npm test
```

生成通常需要数分钟。模型原文件、许可和出处在 `assets/force-models`；数据文件记录 OpenSim 版本和原文件 SHA-256。修改参考模型或动画姿态后须重新生成力表及独立参考文件。

`scripts/verify-force.mjs` 检查所有可行节点的力矩平衡、肌肉容量、插值、同力同色、负重响应及 GPU 资源复用；另对俯卧撑 0、0.5、2.5、5 kg 各检查 1001 个姿态，要求整段均可显示估算。姿态 SHA-256 与实际动画不符时，测试会要求重新生成力表。主项目的 `scripts/qa-activity.mjs` 检查实际 WebGL 着色、负重输入、错误状态、暂停、三档倍速、结构点选、手机布局和隐藏查看器，并验证俯卧撑底部结果、大负重不可行提示及恢复显示。
