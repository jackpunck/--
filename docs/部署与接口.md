# 部署与接口

## 启动

需要 **Node.js 24 或更高版本**。主应用使用 Node 内置 HTTP、SQLite 和加密模块，没有 npm 运行依赖。

```powershell
node --version
npm start
```

电脑访问 `http://localhost:3000`。首次打开后注册账号，再完成个人建档。AI 功能在「个人设置 → AI 服务」中配置：选择预设供应商、填写 API Key、获取并勾选模型，再为各任务选择模型。提供 12 家预设及自定义供应商；未配置时会明确提示。数据默认写入项目 `.data` 目录。

```powershell
# 以下仅为自定义配置示例；按需设置。
$env:PORT = '3000'
$env:HOST = '127.0.0.1'
$env:DATA_DIR = 'D:\FitnessData'
$env:COOKIE_SECURE = 'true'
$env:ALLOW_PRIVATE_AI = 'false'
npm start
```

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址；反向代理部署可设为 `127.0.0.1` |
| `DATA_DIR` | 项目 `.data` | SQLite 数据库和服务器加密密钥目录；相对路径按启动目录解析 |
| `COOKIE_SECURE` | `false` | `true` 时 Cookie 仅通过 HTTPS 发送；本机纯 HTTP 调试不要开启 |
| `ALLOW_PRIVATE_AI` | `true` | 允许本机与局域网模型；开放给非可信用户时应设为 `false` |

主应用提供 `public` 内的网页资源；`/model/` 仅提供精细模型所需文件和署名许可白名单。不会把项目源码、数据库、Excel、开发依赖或任意磁盘文件作为静态目录公开。

## 手机、HTTPS 和离线使用

同一局域网内，手机可访问 `http://电脑局域网IP:3000`，前提是电脑防火墙允许该端口，且服务仍在运行。账号和数据属于这一个服务实例；电脑和手机必须连接同一个实例。

完整 PWA、Service Worker、设备相机接口等体验需要浏览器认可的安全上下文。手机使用普通局域网 HTTP 地址时，浏览器可能禁用这些能力。建议通过具有可信证书的 HTTPS 域名反向代理到本服务。`localhost` 的开发例外不适用于手机上的电脑局域网 IP。

反向代理需要：

- 保留浏览器请求的 `Host`，保证 `Origin` 与 `Host` 一致；服务端会拒绝跨站写请求。
- 允许至少 `12 MB` 的上传请求体；上游响应读取超时建议 `90` 秒以上。
- 使用 HTTPS，并设置 `COOKIE_SECURE=true`。应用不会根据不可信的 `X-Forwarded-Proto` 自动启用安全 Cookie。
- 将 Node 服务限制在代理可访问的地址和端口。代理层按实际部署配置访问控制、请求频率及日志保留。

离线编辑由浏览器 IndexedDB 保存，联网后按记录版本同步。第一次使用、登录、AI 请求、上传新附件和跨设备取回数据需要联网。Service Worker 不缓存鉴权 API 和个人图片；已在服务端上传的附件无法保证离线可查看。浏览器清理站点数据也会清除尚未同步的本地记录。

## AI 协议与支持边界

已实现 **OpenAI 兼容 Chat Completions、Anthropic Messages、Gemini GenerateContent** 三种协议。12 家预设包含 DeepSeek、硅基流动、Kimi、百炼国际、OpenAI、Anthropic、Gemini、OpenRouter、Groq、xAI、Mistral、Cerebras；预设地址与官方依据见 [AI 供应商](AI供应商.md)。

| 协议值 | 对话端点 | 鉴权与消息转换 |
| --- | --- | --- |
| `openai` | `POST {baseUrl}/chat/completions` | `Authorization: Bearer`；`messages`，聊天支持 `stream:true` |
| `anthropic` | `POST {baseUrl}/messages` | `x-api-key`、`anthropic-version: 2023-06-01`；独立 `system`，原生内容块；普通请求 `max_tokens:4096`，流式请求 `8192` |
| `gemini` | `POST {baseUrl}/models/{model}:generateContent`，流式使用 `:streamGenerateContent?alt=sse` | `x-goog-api-key`；`systemInstruction`、`contents`，助手角色转为 `model` |

OpenAI 兼容请求示例：

```text
POST {baseUrl}/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json

{"model":"模型 ID","messages":[...],"stream":false}
```

常用供应商只需填写 API Key 即可获取模型。自定义地址一般包含供应商要求的版本前缀，例如 `/v1` 或 `/v1beta`；也接受以 `/chat/completions` 或 `/messages` 结尾的地址。服务端按协议构造端点。测试连接会用默认模型或指定的已启用模型发送一条简短消息，可能产生供应商调用费用。

- 模型列表由服务端实时查询，支持搜索、勾选多个模型及手动添加 ID。供应商只保存已启用的模型；`model` 是默认测试模型，任务实际使用 `tasks` 与 `taskModels` 指定的供应商和模型。
- 模型发现跟随受支持的分页游标，最多查询 10 页、返回 2000 个模型；达到上限时返回 `truncated:true`。Anthropic、Gemini、百炼使用各自分页参数。专用模型端点只用于未修改地址和协议的对应预设；自定义配置查询自身的 `/models`。
- 模型图片能力仅根据接口能力字段显示为支持、不支持或待确认，不按模型名称猜测。Gemini 仅保留支持 `generateContent` 的模型，Mistral 排除明确不支持聊天的模型，百炼排除明确不输出文本的模型；其他未提供用途信息的列表可能包含非对话模型。
- 图片在 OpenAI 兼容协议中使用 `image_url`，Anthropic 使用 Base64 `image` 内容块，Gemini 使用 `inlineData`。PDF 分别使用 `file` / `file_data`、`document`、`inlineData`；实际能否识别取决于供应商和模型。
- OpenAI 兼容接口可返回 `reasoning_content`。应用以可选 `reasoningContent` 随助手消息保存，连续对话时回传，供要求保留推理上下文的模型使用。此字段不等同于 Anthropic thinking blocks 或 Gemini thought signatures；后两种结构在同轮工具调用的原生消息中保留。
- 聊天支持三种协议的流式输出，以及训练计划、日程任务和今日饮食的读取、新增、修改、删除工具调用。工具调用需要模型自身支持；未实现联网检索或模型自动下载。完整约定见 [AI 对话](AI对话.md)。
- TXT、Markdown、CSV、JSON 按 UTF-8 文本加入上下文；单个文本附件发送给模型时不超过 `200 KB`。不解析 Word、Excel、压缩包或任意二进制文件。
- 上游请求默认超时 `60` 秒；单个用户最多同时 `3` 个 AI 请求；上游响应最多 `2 MB`。不跟随接口重定向。
- 供应商地址仅接受 HTTP/HTTPS，拒绝 URL 内的凭据、查询参数、片段及云元数据地址。发起连接前检查 DNS，并固定检查后的地址，避免二次解析切换到其他地址。禁用内网模式时也会拒绝解析到私有地址的域名。
- 服务端为对话、餐食、规划添加任务提示和用户上下文；不会声称项目已有经过专业审核的医学知识库。用户在聊天中明确要求时，AI 可执行计划、日程和今日饮食变更；只是询问建议时不记账，餐食编辑器的估算仍需确认后入账。工具操作校验账号、参数和版本，并返回实际结果。

餐食模型约定返回：

```json
{
  "items": [{ "name": "熟米饭", "grams": 150, "kcal": 116, "protein": 2.6, "carbs": 25.6, "fat": 0.3 }],
  "note": "份量来自目测，请确认。",
  "confidence": "low"
}
```

`grams` 是实际吃下的份量。`kcal` 和三大营养素均为**每 100 克**的数值；由前端按实际份量换算。模型返回内容由前端验证并展示为草稿。

## 数据、备份和恢复

`.data` 中包含：

| 文件 | 内容 |
| --- | --- |
| `fitness.sqlite` | 用户、密码摘要、会话、记录、附件、加密后的供应商密钥 |
| `fitness.sqlite-wal`、`fitness.sqlite-shm` | SQLite WAL 运行文件，运行时可能存在 |
| `server.key` | 32 字节 AES-256-GCM 服务器主密钥 |

密码使用带随机盐的 scrypt 摘要；会话 Cookie 仅保存随机令牌，数据库保存令牌摘要。供应商 API 密钥使用 AES-256-GCM 加密；个人导出和浏览器读取接口不会返回明文密钥。个人记录与附件在 SQLite 中没有整库加密，应保护数据目录权限、磁盘和备份。

**备份必须同时保留数据库与 `server.key`。** 该密钥绑定这个服务的数据目录，移动到另一台机器时也必须一并迁移。它不是硬件密钥；丢失后已有供应商密钥无法解密，需要重新填写。

最简单可靠的备份方法：停止服务，完整复制 `DATA_DIR` 到受保护位置，再启动服务。不要在运行时仅复制 `fitness.sqlite` 而忽略 WAL。需要在线备份时使用 SQLite 支持的一致性备份工具或 API，并同时备份当前 `server.key`。恢复时停止服务，将完整备份放回配置的数据目录后重新启动。

用户「导出我的数据」得到可阅读的 JSON，包含记录、供应商公开配置、已启用模型、任务供应商与模型选择，以及附件 Base64 内容。它不包含密码摘要、登录会话、API 密钥和服务器主密钥，不能替代完整服务器备份。当前没有个人 JSON 一键导入界面。

升级已有数据库时，启动程序自动增加供应商预设、协议、模型列表及任务模型字段。旧供应商按自定义 OpenAI 兼容配置保留，旧单个模型加入已启用列表；旧任务仍引用原供应商，并回退使用其原模型。已有加密密钥保持不变。

删除账号要求再次提供密码，并级联删除该用户全部记录、附件、供应商配置及所有会话；随后清理当前 WAL。删除不会修改历史备份，也不能远程擦除离线设备已经保存的数据。其他设备再次联网时无法继续使用原会话。

## HTTP 接口

请求使用 JSON；响应使用 JSON，附件下载和流式聊天除外。普通错误返回 `{"error":"可显示的原因"}`；流式开始后的错误通过 SSE `error` 事件返回。账号通过同源、`HttpOnly`、`SameSite=Strict` Cookie 认证。无权限返回 `401`；跨账号附件统一视为不存在，返回 `404`。

前端登录后应为 API 请求设置 `X-Fitness-User: 当前用户ID`。服务端对需要登录的接口及退出登录校验此请求头：若与 Cookie 对应账号不一致，返回 `409`，避免另一标签页切换账号后发送旧账号的资料、AI 上下文或设置。`/api/auth/me`、登录和注册不校验此请求头，以便重新确认当前身份。此请求头是附加身份一致性检查，不能替代 Cookie 鉴权。

| 方法和地址 | 请求 / 响应要点 |
| --- | --- |
| `GET /api/health` | `{ok:true}` |
| `POST /api/auth/register` | `{email,password,name}`；密码 8–256 字符；返回 `{user:{id,email,name}}` |
| `POST /api/auth/login` | `{email,password}`；返回用户并建立 30 天会话 |
| `POST /api/auth/logout` | 注销当前会话 |
| `GET /api/auth/me` | 返回当前用户，未登录 `401` |
| `GET /api/state?userId=...` | `{userId,records}`，包含删除墓碑；若指定用户与会话不同，返回 `409` |
| `POST /api/sync` | `{userId,changes:[{id,kind,data,baseVersion,deleted?}]}`，返回 `{userId,records,conflicts}` |
| `GET /api/providers` | `{providers:[{id,name,presetId,protocol,baseUrl,model,models:[{id,name,vision}],hasKey}],tasks:{chat,meal,planning},taskModels:{chat,meal,planning}}`；`tasks` 的值为供应商 ID 字符串，`taskModels` 的值为模型 ID 字符串 |
| `PUT /api/providers` | `{providers,tasks?,taskModels?}`；完整替换供应商列表，模型必须属于对应供应商的已启用列表；同一目标下 `apiKey` 空或省略保留旧密钥，非空则更新；`clearKey:true` 清除；移除供应商条目会删除其密钥 |
| `POST /api/providers/models` | `{id}` 或 `{provider:{id?,presetId?,name?,protocol?,baseUrl?,apiKey?,models?,model?}}`；可查询尚未保存的配置，返回 `{models:[{id,name,vision}],truncated,message?}`；`vision` 为 `true`、`false` 或 `null` |
| `POST /api/providers/test` | `{id,model?}` 或 `{provider:{...},model?}`；指定模型必须已启用，省略时用供应商默认模型；成功返回 `{ok,message}` |
| `POST /api/ai` | `{task,messages:[{role,content,attachments?:[{id}],reasoningContent?}],context,stream?,requestId?}`；普通模式返回 `{content,model,provider,reasoningContent?}`；聊天 `stream:true` 返回 SSE `meta/delta/tool_result/done/error`，重试保持相同 `requestId` |
| `POST /api/attachments` | `{name,type,data}`；`data` 为纯 Base64，无 `data:` 前缀；返回 `{id,name,type,url,size}` |
| `GET /api/attachments/:id` | 按当前账号鉴权下载；响应禁止缓存 |
| `DELETE /api/attachments/:id` | 删除当前用户未被有效记录引用的附件；仍被引用时返回 `409` |
| `GET /api/export` | 完整个人 JSON 导出，含附件数据，不含密钥 |
| `DELETE /api/account` | `{password}`；删除个人全部服务端数据和会话 |

### 同步与容量

最多配置 20 个供应商，每商最多启用 500 个模型。`tasks` 与 `taskModels` 分开保存，因此同一家供应商的不同模型可分别承担对话、餐食和规划。省略任务映射时尽量保留仍有效的原选择；旧版只提交单个 `model` 的调用方式继续兼容。更换供应商预设、协议或接口地址时，已有密钥不会自动发往新目标，必须重新提供密钥或显式清除。

记录 ID 在一个账号内唯一，允许字母、数字、下划线、连字符、冒号，长度最多 `100`。`kind` 最多 `40` 字符。未删除记录的 `data` 必须为 JSON 对象；服务端保留业务结构的灵活性，不对客户端传入的健康资料作医学真实性校验。

新记录使用 `baseVersion:0`。已存在的记录必须携带服务端最新版本；更新成功后版本加一。版本不匹配不会覆盖服务端内容，`conflicts` 中返回 `{id,server}`，其他无冲突记录仍会保存。删除也增加版本并留下墓碑，防止旧设备把已删除内容重新同步回来。客户端应始终发送 `userId`，防止另一标签页切换账号后误把旧离线队列写入新账号。

每次同步最多 `500` 条、请求体最多 `8 MB`。单个会话记录最多 `2 MB`，其他记录最多 `256 KB`。超过限制应拆分同步批次，或新建会话；服务端返回明确的 `413`，不会静默截断用户记录。

单个上传附件最多 `8 MB`，每用户附件总量最多 `250 MB`。支持 JPEG、PNG、WebP、GIF、PDF 和四种文本格式；不接收 SVG/HTML。每条 AI 消息最多 `6` 个附件，每次 AI 请求附件合计最多 `24 MB`。AI 请求最多 `80` 条用户/助手消息，单条文本最多 `32000` 字符，单条助手 `reasoningContent` 最多 `64000` 字符，上下文最多 `256000` 字符。浏览器应保存完整历史，仅发送近期消息。服务端不接收客户端自定义的 system 消息。

删除会话或餐食等记录时，服务端会清空墓碑中的原文，并回收该记录原来引用、且其它有效记录不再引用的附件。编辑已有记录时移除照片，也会在同步后回收已失去全部有效引用的附件。仍被其它记录共享的图片继续保留。刚上传而尚未存入任何记录的附件不会受这种清理影响。

取消上传后，可调用附件 DELETE 接口清理未引用文件；服务端不会定时扫描删除全部孤立附件，因为离线草稿可能尚未同步引用。账号删除会清理所有附件，包括没有被记录引用的文件。

## 验证

```powershell
npm test
node --test tests/server.test.mjs
```

后端测试在系统临时目录创建独立 SQLite 数据库，并使用本地 HTTP 模拟上游，验证鉴权、跨用户隔离、版本冲突、附件、导出、密钥加密、AI 协议、重启持久化和删除。不会调用真实 AI 服务或写入用户 `.data`。
