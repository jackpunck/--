# 知识条目与审核状态

## 当前范围

`public/knowledge.js`维护5条基础知识：规律阻力训练、记录体重/饮食/活动、代谢预测、生熟重量和每100克可食份量。内容只概括实际查看过的原始研究、专业组织或政府资料，并附原始页面链接。

所有当前条目的状态都是`source-checked`，统一显示：**来源已核对，尚未专业审核**。2026-09-28是本项目核对网页的日期，不是专业人员签署日期，也不应被解释为来源的最新修订日期。当前版本不能宣传拥有“经专业审核的健身知识库”。

`findKnowledge(text)`按关键词选择最多3条卡片。检索不会判断一句话是否正确，也不会因匹配到卡片而认证AI整段回答。没有匹配时返回空列表。供模型使用时要连同来源和`review`字段一起传递，不能只传正文并丢弃审核状态。

## 新增条目

在`knowledgeCards`加入以下字段：

```js
{
  id: 'stable-unique-id',
  title: '一个明确的问题或事实',
  summary: '用自己的语言概括适用条件、结论和必要限制。',
  keywords: ['用于匹配的具体词语'],
  sourceUrl: 'https://原始资料的具体页面',
  sourceName: '机构或研究名及必要日期',
  review: {
    status: 'source-checked',
    date: 'YYYY-MM-DD',
    note: '来源已核对，尚未专业审核'
  }
}
```

新增前打开实际来源，核对正文是否直接支持卡片事实和适用人群。优先原始研究、政府资料、专业组织公开文件；不能只看搜索摘要就推断整个临床结论。只为核对过的段落写摘要，不把机构声誉延伸成对应用算法、默认值或个体建议的认证。

涉及数字时保留单位、对象和范围。应用规则须明确归属于本应用，例如“漏记会限制本应用判断”“整批称重只做份量比例换算”。不把这些产品说明冒称成研究结论。卡片不是疾病诊疗、康复处方或过敏原数据库。

## 专业人工审核

`source-checked`表示开发过程中核对了来源链接与摘要，不能改写成“专业已审”。只有具备相应资格和领域经验的真实审核者完成条目审核，并留下可追溯记录后，才将该**条目**改为`reviewed`。建议补充：

```js
review: {
  status: 'reviewed',
  date: '实际审核日期',
  note: '准确描述完成的审核范围及适用边界',
  reviewerName: '实际审核者',
  reviewerQualification: '经核实的相关资格',
  evidencePath: '审核记录文件路径或受控系统编号',
  reviewedContentVersion: '条目内容版本或摘要哈希',
  nextReviewDate: '约定复核日期'
}
```

上述只是字段示意，不能原样填入占位信息后宣称审核完成。审核必须包含摘要与原文一致性、适用人群、潜在误解、动作或营养限制，以及来源是否被后续证据替代。某一条目的审核不覆盖同页其他资料，也不自动覆盖模型生成的回答。

正文、算法含义或适用范围改变后，原审核应失效并等待重新审核。来源失效、撤稿或明显过时时，应停用相关条目，不继续给新回答提供该卡片。可从数组移除或在后续扩展中加入`withdrawn`状态并确保检索排除；不要只改显示文字却仍传给AI。

## 验证

运行 `node --test tests/knowledge.test.mjs`，检查唯一ID、真实状态、来源链接形状、空匹配、关键词检索及最多3张卡片。测试不能自动核实临床正确性或替代人的专业审核。

应用集成后人工检查：

1. 问“生重熟重如何换算”，确认显示对应卡片，打开可见摘要、源链接和来源核对状态。
2. 问无关问题，确认不硬塞无关知识卡片。
3. 检查AI上下文仍包含审核元信息；没有专业审核记录时，界面与系统提示不得称其为“专业已审”。
4. 打开每个外部来源，确认链接可用且实际内容仍支持摘要。
