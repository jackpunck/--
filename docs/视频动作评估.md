# 视频动作评估

## 当前功能

登录后进入「动作评估」，或从「训练计划」「知识大全」点击视频评估入口。选择视频后，系统先分析身体轨迹，再按已配置的模型进行 AI 识别与点评，不要求用户先选择动作。

原视频和完整骨架序列在浏览器中处理。只使用本机分析时无需 API Key；启用 AI 点评时，视觉模型接收最多 6 张压缩关键画面及检测摘要，文本模型只接收检测摘要。图片不作为附件保存，也不写进报告。当前支持浏览器可解码的 MP4、WebM、MOV，单段最长 120 秒、最大 200 MB；不支持的编码会提示转换。

在「个人中心 → AI 设置 → 任务使用的模型 → 动作点评」单独选择模型。保存供应商时，尚未配置的动作点评会使用该供应商所选的默认模型；已有单独选择会保留。旧账号仅打开页面时不会自动分配模型。使用视觉模型前，应在模型列表中确认其图片能力。动作页面会显示供应商、模型和发送的内容，可关闭自动 AI 点评，分析后再手动请求。

保存配置会核对写入响应，再读取服务器确认四个任务的模型。服务器遗漏动作点评、返回不同模型或无法完成确认时，页面显示错误并保留选择供重试；不会显示保存成功。供应商和任务配置写入按提交顺序执行，早先的读取不会覆盖新保存的模型。

## 多人视频与评估对象

默认从画面中央选择训练者，再依靠连续位置、身体尺度与关节结构跟踪同一个目标。全图检测结合目标区域与左右区域补检，以发现画面较小或偏侧的人物；左右补检先遮去全图已检出的身体区域，避免截断的半身被模型再次当成人物。裁切结果映射回原图并按共同可见关节去重；较少身体上下文的局部预测不能覆盖完整骨架。需要指定其他人时，点击「点选训练者」，页面会回到第一帧；点击自己的上半身，再开始分析。键盘可用方向键移动标记、回车确认。改变目标后需要重新分析。

回放中的目标框与骨架用于核对所评估的人。检测到多人不会直接拒绝整段视频；只有可靠锁定的目标点进入动作分析。目标重叠、跟踪丢失或身份不明确时，相关画面被排除，动作不能跨失锁片段拼接；整段可靠跟踪覆盖率低于 70% 时不评分。持续丢失或无法区分交叉经过的人物后，需要重新选择目标并分析，不自动改评旁人。这里的目标编号只用于同一段视频中的连续跟踪。

AI 关键画面从可靠锁定的片段中选择，至少两个不同时间保留完整场景，用于观察杠铃两端、史密斯导轨、凳面、绳索及胸垫；其余画面保留训练者近景。画面以 `TARGET` 框指出评估对象，模型只能点评该目标，无法看清时保留未知。报告保留选择方式、跟踪覆盖率与人数摘要，原片和完整轨迹不保存。

结果包含：

- 自动识别的动作类别、待确认的变式、完整尝试次数。
- 每项检查的通过、问题或无法判断状态，以及对应证据和纠正建议。
- 每次动作的起止时间、最低点、分项指标和参考分。
- 问题时间点、逐次回看，以及与视频时间对齐的骨架叠加。
- 对应动作的现有 3D 教学。
- 手动保存、跨设备同步、查看和删除报告摘要。

保存报告不会自动完成训练，不保存原视频、完整关键点序列或临时文件地址。关闭页面后，历史报告仍可阅读；骨架回放需要重新选择原视频并分析。

动作报告的前端、本地同步和服务器上限统一为 1 MiB。保存时仅移除与逐项检查重复的旧分项统计，保留全部动作次数、时间、指标、检查与 AI 证据；不会为压缩体积截掉后半段动作。超过上限会明确提示。

## 分析过程

1. 浏览器检查文件、时长、尺寸和编码。
2. 按视频时间采样，缩小分析画面，保持宽高比。兼容的 MP4 使用 WebCodecs 顺序解码；其他文件或不支持的浏览器使用视频逐点解码。
3. 专用 Worker 运行 MediaPipe Pose Landmarker，提取 33 个关键点。
4. 根据身体姿态、支撑点稳定性、关节运动和躯干位移自动识别动作。
5. 检查可见度、多人情况、拍摄角度和连续性，按各动作的主要运动轨迹划分往返；平板支撑按持续时间检查。
6. 计算可观察的指标，输出分项结果及问题时间点。
7. 启用视觉点评时，提取起始、代表动作、问题片段等关键画面。AI 结合器械和可见外形复核动作变式，并给出有画面时间依据的纠正建议。
8. 本地检查与 AI 观察合并后，由确定性的规则计算参考分。AI 不能自行打分、覆盖本地失败项，或把视频质量不合格改成可评分。

AI 确认同类动作的变式后，会按该变式重新分析完整轨迹。原先已观察到的问题仍保留为带时间的证据并限制总分，不能因为重新划分动作起止点而消失。没有完整动作过程时，AI 可补充动作名称，但不会从几张画面补造次数或分数。

姿态检测使用 MediaPipe；身体轨迹分类和评分使用本项目的时序规则。设备、握法等无法由 33 个姿态点充分区分的信息交给视觉模型核验。模型无法确认时保留候选，不把猜测写成已确认动作。

## 动作目录

评估目录包含原有 25 个教学动作，以及 7 个卧推和划船变式，共 32 项，按 17 类身体运动组织检查。新增变式共用对应家族的姿态检查，不提供尚未制作的 3D 教学入口；旧动作 ID 和历史名称保持原含义。目录覆盖不代表已经测得所有动作的识别准确率。

| 类别 | 动作 | 主要检查 |
| --- | --- | --- |
| 深蹲 | 徒手深蹲、高脚杯深蹲 | 幅度、全过程躯干前倾、起身肩髋同步、可见脊柱外形 |
| 俯卧撑 | 俯卧撑 | 幅度、肩髋踝连线、可见脊柱外形 |
| 水平推胸 | 哑铃/杠铃/史密斯平凳卧推及对应上斜变式、器械推胸 | 肘部活动、躯干变化、支撑与器械设置 |
| 垂直拉 | 高位下拉、辅助引体向上 | 活动幅度、躯干摆动、器械设置 |
| 水平划船 | 坐姿绳索划船、单臂哑铃划船、杠铃俯身划船、器械划船、胸托划船 | 拉回幅度、肩部向耳部上提、躯干借力、可见脊柱外形 |
| 肩部 | 哑铃推举、侧平举、俯身飞鸟 | 各自运动幅度、躯干或上臂稳定、肩部上提 |
| 肘部孤立 | 哑铃弯举、锤式弯举、绳索下压、颈后臂屈伸 | 屈伸肘幅度、上臂稳定、器械和握持 |
| 髋铰链 | 哑铃罗马尼亚硬拉 | 髋部活动、膝部变化、可见脊柱外形、负重轨迹 |
| 腿部 | 反向箭步蹲、腿弯举、腿屈伸、站姿提踵 | 对应关节的活动幅度、髋部及躯干稳定 |
| 臀部与核心 | 臀桥、平板支撑、卷腹 | 对应身体连线、保持时间或运动幅度、头颈与脊柱外形 |

卧推、划船的精确名称需要视觉模型返回结构化 `action.observations`：器械、支撑姿态、运动方向、单侧/双侧动作、具体依据和画面时间。各项必须符合目录的 `recognitionRules`，并与动作确认共享至少两个实际发送的关键帧时间。例如哑铃卧推不能使用杠铃依据确认，史密斯需观察杆与导轨连接，平凳与上斜不能仅按画面旋转角度判断。缺少依据或相互矛盾时只列候选，不确认精确动作。结果与历史报告显示识别依据；即使画面足以确认名称，连续姿态不足也仍不评分。

半身划船可利用可见肩、肘、腕、髋的连续拉回轨迹，脚不必作为上肢识别的硬前提；髋或动作臂看不清仍保留质量限制。单臂划船重评时选择持续可见的活动侧，不以静止支撑臂替代，也不跨缺失片段拼接。卧推按每段最先观察到的极值端划分完整往返，允许伸直或弯曲起点；中途开始或没有回程的半次不补计。

## 评分范围

每种动作有独立的检查项和权重，见 `public/motion-catalog.js`。深蹲重点区分「肩髋连线前倾」「起身肩髋同步」与「脊柱自然位置」；划船区分「耸肩」「躯干借力」与「拉回幅度」。躯干倾斜会改变髋膝负荷，深度与变式应结合个体能力；不能把所有前倾都当作错误。动作要领参考 [NASM 深蹲生物力学](https://www.nasm.org/resource-center/blog/training/biomechanics-of-the-squat)。

| 证据情况 | 评分处理 |
| --- | --- |
| 已观察到严重问题 | 总分最高 49 |
| 关键检查项失败 | 总分最高 59 |
| 存在其他检查失败 | 总分最高 79 |
| 关键项无法判断，或只看过离散画面 | 最高 69，标为部分证据参考分，不算合格 |
| 其他检查项未完整核验 | 最高 84，不算完整核验通过 |
| 没有足够可观察项、动作未确认或硬性质量检查失败 | 不评分 |

`observedScore` 只按可观察项归一化；`scoreCoverage` 表示完整动作过程已核验的检查权重比例，离散关键画面不会提高这项覆盖率；最终 `score` 同时受上限限制。未知项不会被当作已通过，也不会自动被描述为动作错误。关键画面中的 pass 只代表这些画面，不能证明整组动作持续合格。

具体阈值和计算见 `public/motion-analysis.js`，结果保留 `version`。这些阈值是可解释的工程规则，仍需要更多人物与教练标注视频校准；不是适用于所有身材、动作变式的统一训练标准。

- 角度在 `x × 视频宽度`、`y × 视频高度` 的统一像素坐标中计算，不直接混合归一化 x/y/z。
- 单目估计的 world/z 坐标不被当成实际测得的三维身体结构。
- 浅蹲、浅俯卧撑只要具有完整往返就作为一次尝试评估，并反馈幅度不足。
- 未观察到起始或回到顶端的动作，不补造次数、不补评分。
- 静止、未知动作、无法锁定训练者、明显遮挡或不合适的视角可返回「不足以评分」。已识别出动作时保留动作类型。
- 长时间关键点缺失会切开动作片段，不跨缺失拼接次数。
- 视频中的准备、结束姿态可排除在评估区间外，结果保留 `observedActiveRange`。已知原始帧率低于 5 fps 时拒评；15 fps 分析采样率不代表原视频有 15 fps 的信息量。
- MP4/M4V/MOV 的简单时间轴可读取原始帧率；WebM、复杂编辑时间轴或解析失败时该值为 `null`，界面说明原始帧率未验证。此时无法可靠排除低帧率视频，不能将它当作通过了原始帧率检查。

`exerciseConfidence` 是规则证据强度，未经概率校准，不能当作识别准确率。分数是工程检查的参考值，不能解释为「动作标准程度为某个百分比」。

33 个姿态点不包含完整脊柱曲线，因此本地算法不会用肩髋连线证明腰椎中立。视觉模型可以指出已提供画面中可见的圆背、过伸等外形线索，遮挡或视角不足时必须保留未知；它同样不能测量真实腰椎的三维中立位。足底受力、实际肌肉发力和混合动作仍不在已验证范围。拥挤场景、长期遮挡和外形相似的人交叉经过仍可能失锁。现有 3D 模型用于教学，不是评分金标准。

划船耸肩检查比较发力阶段与还原阶段的肩耳距离，并要求变化持续可见；头部移动或耳点遮挡时保留未知。动作指导参考 [ACE 坐姿划船](https://www.acefitness.org/resources/everyone/exercise-library/168/seated-row/)与[绳索划船](https://www.acefitness.org/resources/everyone/exercise-library/48/seated-row/)。这些来源支持动作要领，未验证本项目的像素阈值或分数。

侧平举、飞鸟中的肩部变化不套用划船耸肩阈值。33 点不能描述完整肩胛运动，这两类动作的肩部检查由画面补充核验，本地保留未知。

原有 Node 服务即可启动，不需要新增 Python 服务。本机分析不依赖云端；AI 点评使用用户配置的供应商。静态模型资产约 32 MB，按需加载。Service Worker 在实际使用后缓存模型；部署时必须同步应用模块、Worker、WASM 和模型，变更时更新缓存版本。

`POST /api/motion/coach` 要求登录，只使用当前账号配置的 `motion` 任务。每张图片不超过 512 KiB、长边不超过 1280，总计不超过 2 MiB，最多 6 张；浏览器默认长边 640，整体证据包小于 1.9 MB。服务端校验类型、图像头、尺寸、时间和分析摘要，剔除模型引用的未知检查项、无效时间及无证据判断。模型没有工具权限，不能修改训练或健康记录。

服务器需提供 `.wasm` 的 `application/wasm`、JavaScript MIME 与 `.task` 二进制 MIME；CSP 允许同源 Worker、WASM 编译及本地 `blob:` 视频。本项目已配置，未开放普通 JavaScript 的 `unsafe-eval`。

```powershell
npm start
npm test
npm run check
npm run motion:assets
```

`motion:assets` 只检查资源散列，不联网。缺少模型文件时运行 `node scripts/setup-motion-assets.mjs`，按固定来源恢复，校验不匹配会失败。

## 验证方法和实际边界

自动化测试覆盖正常/浅动作、镜像、纵横比、不同采样率和速度、静止、未知动作、缺少首尾、关键点缺失、前视、多人，以及真实视频提取的身体关键点。测试通过证明软件行为与回归结果；不等于已测得面向所有用户的准确率。

真实模型测试使用本地 Edge，检查完整时间采样、页面响应、GPU/CPU、空画面、多人、初始化失败回退、取消和 Worker 释放。界面测试使用隔离账号和临时数据库，不读取用户账号或模型密钥。

浏览器测试依赖 Playwright。设置 `QA_PLAYWRIGHT` 为本机 `playwright/index.mjs` 路径，`QA_BROWSER` 为浏览器可执行文件路径后运行：

```powershell
node scripts/qa-motion-pipeline.mjs path/to/squat.mp4 path/to/pushup.mp4
node scripts/qa-motion.mjs path/to/squat.mp4 path/to/pushup.mp4
node scripts/qa-motion-coach.mjs path/to/squat.mp4
node scripts/qa-motion-coach.mjs --reports-only
node scripts/qa-motion-target.mjs
node scripts/qa-motion-benchmark.mjs .qa/motion-fixtures
```

设置 `QA_MOTION_OFFLINE=1` 后，界面验证还会断网、重载、重新分析本地文件、保存并联网同步。它也验证失败退出后的页面恢复、训练/知识入口以及 3D 教学。

测试产物写入 `.qa/`，原视频不随应用分发。数值回归 fixture 保留来源说明；原两段计次数值附原文件散列和模型版本，新增跟踪回归记录公开数据集与许可。它们仅保留身体关节，没有图像或面部点，也不是教练评分真值。

### 本次扩展的验证

- 32 个动作的规则可达性、完整往返和专属问题使用构造的身体轨迹验证；覆盖深蹲持续前倾、肩髋不同步、划船动态耸肩、半身/单臂划船、卧推两种起点、头部移动及耳点缺失等。这验证规则行为，不是 32 个动作的真人识别准确率。
- 器械识别契约覆盖全部卧推/划船条目，拒绝缺失或冲突的器械、支撑及时间依据。浏览器 `--reports-only` 验证模拟上游响应通过真实 HTTP 清洗、保存和历史展示；无需视频，但不验证真实模型的器械识别准确率。
- AI 集成使用真实浏览器、HTTP、JPEG 提取和报告保存，模型上游使用可控模拟响应；验证独立模型路由、严格合并、逐次问题时间、未知项、失败恢复、取消和手机布局。没有使用用户模型密钥，未把模拟输出当成真实模型点评效果。
- 另外提取 12 段公开真人视频的完整姿态序列，涵盖弯举、推举、划船、侧平举、箭步蹲、髋推和硬拉；来源、许可和 SHA256 见 `scripts/motion-sample-sources.json`，可用 `node scripts/fetch-motion-samples.mjs --verify` 复核本地文件。动作和质量标签来自数据作者，未提供细分错误或教练分数。
- 弯举、箭步蹲、侧平举样例可以进入相应动作类别；斜向划船会保留划船/弯举候选，等待视觉确认。传统杠铃硬拉与髋推不会被强行当成目录中的哑铃罗马尼亚硬拉或地面臀桥。

最终多人推理版本又提取了侧平举与箭步蹲真人样例：前者可靠跟踪 222/274 帧，末段身份不明后停止接纳画面，前段划分出 2 次完整动作；后者 122/122 帧锁定，划分出 3 次完整动作。两者仍需视觉确认目录中的具体变式。轨迹控制等问题尚无独立人工逐次标注，不能把触发规则或较低分数当作已证实的纠错准确性。这两段走兼容视频解码路径，18.25 秒和 8.08 秒视频分别耗时约 41.55 秒和 17.93 秒，明显慢于顺序解码样例。

多人回归包含真实健身房旁观者，以及两段由公开真人素材拼接的明确标记样例；后者用于验证中央选择、侧边点选和目标离场，不能当作自然交互数据。测试同时检查原画面目标框、实际检测人数和目标动作，固定的跟踪编号本身不能证明选对了人。

2026-10-03 最终六场景真实模型回归通过：

最终自动化测试 363 项通过；另有 15 项 AI 点评浏览器流程检查通过。真实模型的 CPU 推理、GPU 初始化失败回退、取消与 Worker 释放也通过。长报告回归使用 119 秒重复的真实姿态序列，经规则分析得到 74 次动作并合并受控 AI 点评，446,827 字节的完整报告在前端校验、本地同步与真实 HTTP 保存后读回一致；这不是新增真人质量标注样本。

### 旧版基线与发现的问题

下面记录升级前的两动作基线，用于保留已知漏检；不是新版 25 动作识别效果的证明。升级前真实样例识别深蹲 5 次完整、俯卧撑 11 次完整及末尾 1 次未回到顶端；接近正面的深蹲保留类型但拒绝侧面评分，开合跳未判成支持动作。

另使用 [Mendeley 数据集第 1 版](https://data.mendeley.com/datasets/kgbb3yn47p/1)的 subject_001/002、深蹲/俯卧撑、good/bad、side 配对视频验证，许可 CC BY 4.0。公开来源、作者 SHA256、目录标签、转码参数收录在 `tests/fixtures/motion-video-sources.json`；原片只保留于本机 `.qa/motion-fixtures/`。HEVC 原片仅在 QA 中转为 H.264；FFmpeg 未加入生产依赖。作者只给 good/bad 二元标签，没有具体错误类型或教练评分。

**旧版漏检：**subject_001 的 bad 深蹲视频下蹲幅度很深，旧版 HTML 解码基线的膝角、肩髋连线和轨迹规则给出约 100 分，未检出作者的 bad 标签；顺序解码因检测到多人而拒评，不能将这种拒评当作质量判断正确。旧版 bad 俯卧撑后续多次浅幅度可触发幅度提示，参考分约 66–67 分；极浅动作计次会受姿态噪声影响。新版要求中立位等未知检查项限制分数，但降低上限也不能算作成功检出具体错误。

**旧版多人漏检。**升级前每 0.5 秒运行一次人数检查，可漏掉短暂入镜、较小或被遮挡的旁观者。subject_002 的 good 俯卧撑画面有真实旁观者，但旧版 59 次人数检查均只返回 1 人，仍输出评分；不能把它当作干净的单人准确率证据。新版改为逐帧多姿态候选与连续目标匹配，仍需保留这类困难场景做回归。

这些结果说明当前版本适合检查列出的可见指标，尚不能声称全面判断动作是否标准。12 段真实视频用于功能、视角、未知动作、作者质量标签和多人场景的对照，不能据此计算面向一般用户的准确率。

### 本机速度实测

新增逐帧多候选、目标区域推理与左右补检后，完整页面流程的已缓存模型实测为：11.2 秒深蹲用时 7.17 秒，17.76 秒俯卧撑用时 6.31 秒。两段分别保持自动识别 5 次、11 次；离线重载分析、保存与恢复同步通过。增加人物检测会多占用推理时间。

#### 单目标旧版速度基线

以下为新增逐帧多候选及区域补检前的速度基线。Windows / Edge 154 / NVIDIA RTX 4070 Laptop，完整页面流程、GPU 推理，已缓存模型：

| 视频 | 视频时长 | 优化前 HTML 解码耗时 | 顺序解码分析耗时 |
| --- | ---: | ---: | ---: |
| 示例深蹲，5 次 | 11.20 秒 | 12.00 秒 | 4.96 秒 |
| 示例俯卧撑，11 次完整 | 17.76 秒 | 17.07 秒 | 2.61 秒 |

两条路径都分析完整的 15 fps 时间采样点。耗时含解码、模型初始化与推理，不含用户选文件时间；首次下载约 32 MB 模型、手机或 CPU 回退会更慢。这是本机实测，不是其他设备的时延保证。

早期 HTML 基线在部分帧边界会因浏览器的微秒截断选中前一帧。当前兼容路径已加 2 微秒 seek 容差并限制在片尾以内，报告时间仍保留原采样值；真实视频的原帧时间戳核验通过。顺序路径直接根据原始 PTS 选帧，两种后端的像素和评分不能假设完全相同。
