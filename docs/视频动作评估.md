# 视频动作评估

## 当前功能

登录后进入「动作评估」，或从「训练计划」「知识大全」点击视频评估入口。选择视频后，系统自动判断徒手深蹲或标准俯卧撑，不要求用户先选择动作。

视频在浏览器中处理，不发送到 AI 供应商，也不上传原视频。无需配置 API Key。当前支持浏览器可解码的 MP4、WebM、MOV，单段最长 120 秒、最大 200 MB；MP4/MOV 是容器，里面的 HEVC 等编码可能无法在当前设备播放，界面会提示转换为 H.264 MP4 或 WebM。

结果包含：

- 自动识别的动作、完整尝试次数和达到当前规则的次数。
- 每次动作的起止时间、最低点、分项指标和参考分。
- 问题时间点、逐次回看，以及与视频时间对齐的骨架叠加。
- 对应动作的现有 3D 教学。
- 手动保存、跨设备同步、查看和删除报告摘要。

保存报告不会自动完成训练，不保存原视频、完整关键点序列或临时文件地址。关闭页面后，历史报告仍可阅读；骨架回放需要重新选择原视频并分析。

## 分析过程

1. 浏览器检查文件、时长、尺寸和编码。
2. 按视频时间采样，缩小分析画面，保持宽高比。兼容的 MP4 使用 WebCodecs 顺序解码；其他文件或不支持的浏览器使用视频逐点解码。
3. 专用 Worker 运行 MediaPipe Pose Landmarker，提取 33 个关键点。
4. 根据身体姿态、支撑点稳定性、关节运动和躯干位移自动识别动作。
5. 检查可见度、多人情况、拍摄角度和连续性，按下降、底部、上升阶段划分动作。
6. 计算可观察的指标，输出分项结果及问题时间点。

姿态检测使用机器学习模型；动作分类和评分使用本项目的时序规则。中文反馈直接来自检测到的问题，不需要让通用大模型猜测分数。

## 评分范围

| 动作 | 分项 | 权重 |
| --- | --- | --- |
| 深蹲 | 可见屈膝幅度、肩髋连线前倾、轨迹控制 | 45%、35%、20% |
| 俯卧撑 | 可见屈肘幅度、肩髋踝连线、轨迹控制 | 40%、40%、20% |

具体阈值和计算见 `public/motion-analysis.js`，结果保留 `version`。这些阈值是可解释的工程规则，仍需要更多人物与教练标注视频校准；不是适用于所有身材、动作变式的统一训练标准。

- 角度在 `x × 视频宽度`、`y × 视频高度` 的统一像素坐标中计算，不直接混合归一化 x/y/z。
- 单目估计的 world/z 坐标不被当成实际测得的三维身体结构。
- 浅蹲、浅俯卧撑只要具有完整往返就作为一次尝试评估，并反馈幅度不足。
- 未观察到起始或回到顶端的动作，不补造次数、不补评分。
- 静止、未知动作、多人、明显遮挡或不合适的视角可返回「不足以评分」。已识别出动作时保留动作类型。
- 长时间关键点缺失会切开动作片段，不跨缺失拼接次数。
- 视频中的准备、结束姿态可排除在评估区间外，结果保留 `observedActiveRange`。已知原始帧率低于 5 fps 时拒评；15 fps 分析采样率不代表原视频有 15 fps 的信息量。
- MP4/M4V/MOV 的简单时间轴可读取原始帧率；WebM、复杂编辑时间轴或解析失败时该值为 `null`，界面说明原始帧率未验证。此时无法可靠排除低帧率视频，不能将它当作通过了原始帧率检查。

`exerciseConfidence` 是规则证据强度，未经概率校准。界面显示「识别依据充分/有限」，不把它当作识别准确率。100 分仅表示本次通过了当前检查项。

当前无法可靠判断腰椎弯曲、膝内扣、足底受力、肩胛运动或实际肌肉发力。现有 3D 模型用于教学，不是评分金标准。跪姿俯卧撑、负重变式、混合动作和多人目标选择尚未专门验证。

## 文件与部署

| 文件 | 作用 |
| --- | --- |
| `public/motion-view.js`、`public/motion.css` | 视频、结果、回放和历史界面 |
| `public/motion-video.js` | 视频读取、采样、进度、取消和资源释放 |
| `public/motion-worker.js` | 后台姿态推理、GPU 初始化失败后回退 CPU |
| `public/motion-decode.js` | MP4 分离与顺序解码，按呈现时间选取全部采样点 |
| `public/motion-analysis.js` | 自动分类、连续动作分段、分项评分 |
| `public/vendor/mediapipe/` | 固定版本 JS、WASM、Full 模型、许可证和校验清单 |
| `public/vendor/mp4box/` | 固定版本 MP4Box，含 BSD-3-Clause 许可与校验清单 |
| `tests/motion-*.test.mjs` | 分类、评分、视频边界、真实关键点回归、HTTP 隔离 |
| `scripts/qa-motion-pipeline.mjs` | 真实浏览器、真实模型、完整采样及回退验证 |
| `scripts/qa-motion.mjs` | 真实上传选择、分析、保存同步、回放、取消和手机布局 |
| `scripts/qa-motion-benchmark.mjs` | 重评已提取的真人关键点，列出分类、计次、分项结果与耗时 |

原有 Node 服务即可启动，不需要新增 Python 服务或云端 API。静态模型资产约 32 MB，按需加载。Service Worker 在实际使用后缓存模型；部署时必须同时更新应用代码、Worker、WASM 和模型。模型变更需同步修改资源清单和 Service Worker 缓存版本。

服务器需提供 `.wasm` 的 `application/wasm`、JavaScript MIME 与 `.task` 二进制 MIME；CSP 允许同源 Worker、WASM 编译及本地 `blob:` 视频。本项目已配置，未开放普通 JavaScript 的 `unsafe-eval`。

```powershell
npm start
npm test
npm run check
npm run motion:assets
```

`motion:assets` 只检查资源散列，不联网。缺少模型文件时运行 `node scripts/setup-motion-assets.mjs`，按固定来源恢复，校验不匹配会失败。

## 验证方法和实际边界

自动化测试覆盖正常/浅动作、镜像、纵横比、不同采样率和速度、静止、未知动作、缺少首尾、关键点缺失、前视、多人，以及真实视频提取的身体关键点。测试通过证明软件行为与回归结果；不等于已测得面向所有用户的准确率。

真实模型测试使用本地 Edge，检查完整时间采样、页面响应、GPU/CPU、空画面、多人、初始化失败回退、取消和 Worker 释放。界面测试使用隔离账号和临时数据库，不读取用户账号或模型密钥。

浏览器测试依赖 Playwright。设置 `QA_PLAYWRIGHT` 为本机 `playwright/index.mjs` 路径，`QA_BROWSER` 为浏览器可执行文件路径后运行：

```powershell
node scripts/qa-motion-pipeline.mjs path/to/squat.mp4 path/to/pushup.mp4
node scripts/qa-motion.mjs path/to/squat.mp4 path/to/pushup.mp4
node scripts/qa-motion-benchmark.mjs .qa/motion-fixtures
```

设置 `QA_MOTION_OFFLINE=1` 后，界面验证还会断网、重载、重新分析本地文件、保存并联网同步。它也验证失败退出后的页面恢复、训练/知识入口以及 3D 教学。

测试产物写入 `.qa/`，原视频不随应用分发。两份数值回归 fixture 包含来源、原文件散列和模型版本，仅保留身体关节，没有图像或面部点。这些示例不是教练评分真值。

当前真实样例已验证：深蹲 5 次完整；俯卧撑 11 次完整及末尾 1 次未回到顶端；另一段接近正面的深蹲能识别类型，但不输出侧面评分；开合跳未被误判为支持的动作。实际耗时依赖设备、解码方式和视频编码，应以测试输出的 `elapsedMs` 为准。

另使用 [Mendeley 数据集第 1 版](https://data.mendeley.com/datasets/kgbb3yn47p/1)的 subject_001/002、深蹲/俯卧撑、good/bad、side 配对视频验证，许可 CC BY 4.0。公开来源、作者 SHA256、目录标签、转码参数收录在 `tests/fixtures/motion-video-sources.json`；原片只保留于本机 `.qa/motion-fixtures/`。HEVC 原片仅在 QA 中转为 H.264；FFmpeg 未加入生产依赖。作者只给 good/bad 二元标签，没有具体错误类型或教练评分。

**已知漏检：**subject_001 的 bad 深蹲视频下蹲幅度很深，HTML 解码基线下，现有膝角、肩髋连线和轨迹规则给出约 100 分，未检出作者的 bad 标签；顺序解码版本因检测到多人而拒评，不能将这种拒评当作质量判断正确。bad 俯卧撑视频后续多次浅幅度动作可触发幅度提示，参考分约 66–67 分；极浅动作的计次会受姿态噪声影响。

**多人检测也会漏检。**多人检查约每 0.5 秒运行一次，可漏掉短暂入镜、较小或被遮挡的旁观者。subject_002 的 good 俯卧撑画面中有真实旁观者，但本次 59 次多人检查均只返回 1 人，仍输出评分；不能把它当作干净的单人准确率证据。当前仅能拒绝已检测到的多人，尚未实现可靠的目标选择与锁定。

这些结果说明当前版本适合检查列出的可见指标，尚不能声称全面判断动作是否标准。12 段真实视频用于功能、视角、未知动作、作者质量标签和多人场景的对照，不能据此计算面向一般用户的准确率。

### 本机速度实测

Windows / Edge 154 / NVIDIA RTX 4070 Laptop，完整页面流程、GPU 推理，已缓存模型：

| 视频 | 视频时长 | 优化前 HTML 解码耗时 | 顺序解码分析耗时 |
| --- | ---: | ---: | ---: |
| 示例深蹲，5 次 | 11.20 秒 | 12.00 秒 | 4.96 秒 |
| 示例俯卧撑，11 次完整 | 17.76 秒 | 17.07 秒 | 2.61 秒 |

两条路径都分析完整的 15 fps 时间采样点。耗时含解码、模型初始化与推理，不含用户选文件时间；首次下载约 32 MB 模型、手机或 CPU 回退会更慢。这是本机实测，不是其他设备的时延保证。

早期 HTML 基线在部分帧边界会因浏览器的微秒截断选中前一帧。当前兼容路径已加 2 微秒 seek 容差并限制在片尾以内，报告时间仍保留原采样值；真实视频的原帧时间戳核验通过。顺序路径直接根据原始 PTS 选帧，两种后端的像素和评分不能假设完全相同。
