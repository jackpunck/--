# 视频动作评估

## 当前功能

本机提取客观运动数据，AI 结合这些数据与关键图片判断动作，并告诉用户怎样纠正。结果包含动作名称、一句结论和最多 3 条重点建议：

- **动作基本标准**：说明继续保持的方面。
- **动作需要调整**：说明具体问题、对应片段和下一组可执行的调整。
- **暂时无法判断**：说明还看不清什么，以及怎样补拍。

本地不再识别动作类别、划分次数、执行姿态规则或计算分数。AI 返回后也不会按动作名称重新运行本地分析。当前结果和历史界面均不展示分数、规则清单或逐次指标面板。

登录后进入「动作评估」，或从训练计划、知识大全进入。单段最长 120 秒、最大 200 MB。支持手机常见 MP4、MOV，以及 M4V、WebM、MKV、AVI、3GP、3G2、MPG/MPEG、TS/MTS/M2TS、OGV、WMV、FLV。先尝试浏览器直接读取画面；不能读取时，由本机软件解码器直接读原片。选片只读取信息和首帧，之后即可点选训练者并开始分析。仅音轨可播放而画面尺寸为 0 的情况也会走软件解码。动作名称由 AI 判断，不要求先手动选择。

软件解码使用随项目提供的单线程 FFmpeg WebAssembly，处理 HEVC 等浏览器不支持的编码，约 32 MB 的组件按需加载并缓存。原视频不上传、不改写，不生成中间 MP4。解码器按 15 Hz 输出长边不超过 960 像素的画面，在同一 Worker 内立即进行姿态推理，不累积整段未压缩画面。HLG/PQ HDR 转为 SDR，手机旋转方向、像素比例和时序一并处理。分析显示进度，取消、换视频或离开页面会终止 Worker。能否处理仍取决于文件实际编码、文件完整性与设备可用内存。

软件模式分析完成后提供采样画面回放：默认每秒 5 张、长边不超过 640 像素，不含声音；滑块与 AI 建议可跳转到对应画面，骨架按显示画面的时间对齐。回放 JPEG 仅保留在当前页面，总量限制 64 MiB，超过后均匀减少回放帧，完整 15 Hz 骨架不受影响。AI 需要的最多 6 张图片另外从原片按相同采样时序读取，再裁剪和压缩。原生可播放的视频继续使用原播放器。离开页面释放首帧、回放图片与临时分析数据。

在「个人中心 → AI 设置 → 任务使用的模型 → 动作点评」选择模型。视觉模型接收图片与完整数据；纯文本模型只接收数据，不能补充器械及外形信息，动作身份可能保持未知。保存供应商时，尚未配置的动作点评会使用该供应商的默认模型，已有独立选择会保留；保存后会读取服务器确认配置。

启用 AI 时，全部数据完成评价后才展示结果并允许保存。等待期间可以取消、阅读历史报告，失败后可以重试。只查看本机分析时显示「AI 尚未评价」，可回放视频和骨架，不产生动作是否标准的结论，也不能保存为 AI 报告。

## 实际处理流程

1. **读取视频并锁定训练者。** 检查格式、尺寸和时长，使用浏览器或本地软件解码器读取首帧，默认选择中央训练者，也可以在第一帧点选。
2. **提取完整采样骨架。** 专用 Worker 使用 MediaPipe Pose Landmarker，按每秒 15 帧保存 33 个关键点、已有世界坐标、置信度、缺失情况和人物跟踪状态。
3. **进行一次客观测量。** 按实际分析画面的宽高换算图像坐标，逐帧计算左右两侧各 6 项二维投影角度，同时记录质量信息；不判断动作对错。
4. **选择最多 6 张关键图片。** 保留起始、中部、结束位置，优先补充角度变化的极值时刻，再以时间分布补足画面。极值只用于覆盖不同姿态，不表示动作错误。
5. **交给 AI。** 第一份完整数据包同时附带关键图片。若全部数据只有一包，这一次调用直接形成最终评价；数据较长时，剩余批次只发送文本并共享首次识别的动作背景，最后结合图片与全部批次结果汇总。
6. **校验证据并展示。** 核对 AI 引用的骨架帧、图片时间和测量路径，显示结论与建议。程序不计算分数，也不执行第二次动作分析。

第一步后的姿态提取和客观测量只执行一遍。重试 AI 请求复用当前页面已提取的数据；更换视频或评估对象后才需要重新提取。

### 本地数据包含什么

完整骨架由 `poseData` 传输：

- 每个采样时刻的 `time`，以及解码器提供时的实际画面时间 `sourceTime`。
- 全部 33 点的 `x/y/z/visibility/presence`，本地已有的 `worldLandmarks`，以及字段顺序和坐标说明。
- 空姿态帧、缺失字段、显式 `null` 与零值；缺失置信度不会被改成零。
- 每帧人数、目标编号、锁定／失锁／身份不明状态与边框。
- 视频的显示尺寸、采样频率、已知源帧率、模型版本和解码信息。软件路径记录原片旋转和像素比例修正后的显示尺寸与源帧率；推理时等比例缩小画面，归一化骨架坐标继续对应完整画面。证据图片使用与骨架一致的采样时序，不把请求时间伪装成已知源帧时间。

`fullAnalysis` 使用 `motion-observations-v1`，包含 `version`、`quality`、逐帧 `measurements`，以及可选的人物跟踪元信息。每个输入帧对应一条测量记录，不按动作阶段裁切，不删除暂停或缺失片段：

| 每侧测量字段 | 含义 |
| --- | --- |
| `elbowAngle` | 肩—肘—腕夹角 |
| `shoulderAngle` | 髋—肩—肘夹角 |
| `hipAngle` | 肩—髋—膝夹角 |
| `kneeAngle` | 髋—膝—踝夹角 |
| `bodyAlignmentAngle` | 肩—髋—踝夹角 |
| `torsoLean` | 肩髋连线相对画面竖直方向的倾斜角 |

这些是按视频宽高换算后的二维投影角度，不是真实三维关节角。身体点不可用时，该测量为 `null`。`quality` 记录总帧数、至少有一项可测角度的帧数、可测比例、源帧率、目标跟踪覆盖率和缺失原因；“该帧可测”不等于全身都看得清。

AI 可以直接引用骨架帧，也可以引用客观测量，例如 `["measurements", 20, "left", "elbowAngle"]`。服务器核对引用是否存在、是否属于实际发送的批次，以及对应的时间；不接受编造的索引、图片时间或测量路径。

### 完整数据怎样分批

数据使用 `pose-tables-f32-v1` 点表编码，提取重复常量，并共享图像坐标与世界坐标中完全相同的置信度字段。原本精确属于 float32 的数值使用可还原原值的最短十进制表示，其余数值保留原精度。编码不减少帧数、关键点或世界坐标，零值与缺失值保持不同含义。

每个数据包最多 64,000 个字符。第一包连同图片先完成评价；剩余包最多并发两个请求，仅发送文本。需要汇总时，全部批次参与，过长的中间结果会分层汇总。一个包只需一次调用，多包才增加汇总调用；没有单独的图片预识别调用。

完整数据较长时仍可能产生较多模型调用与费用。全部批次完成后才发布最终报告；任一部分失败，不会静默改成摘要或发布部分结果。

### 等待、超时与取消

浏览器通过 SSE 接收阶段、已完成批次和耗时，服务器每 15 秒发送保活消息。动作点评每次上游调用默认超时为 180 秒，不是整段分析的总时限。

超时调用自动重试一次，本次请求中已经完成的批次保留。重试仍失败时显示错误；再次手动评价会发起新请求，中间结果不跨请求保存。用户取消会终止当前模型调用与后续处理。保活和重试不能保证供应商一定响应成功。

使用 DeepSeek 官方地址 `api.deepseek.com`、OpenAI 兼容协议及 `deepseek-flash`／`deepseek-v4-pro` 时，动作点评关闭额外思考并要求 JSON 输出。该设置只用于这些已匹配的官方模型，不发给其他服务或任务。

## 人物、图片与动作名称

默认跟踪中央训练者，可在第一帧点选自己的上半身；键盘可用方向键移动标记、回车确认。全图检测结合目标区域及左右区域补检，并按共同可见关节去重。目标重叠、丢失或无法确认身份时，相关测量保持未知，不能改评旁人或补造连续轨迹。

AI 图片来自可靠锁定的片段。有足够可用画面时，至少两个不同时间保留完整场景，帮助观察器械和身体支撑；其余图片可展示训练者近景。`TARGET` 框标明评估对象。原视频留在浏览器，启用 AI 后完整骨架、客观测量和压缩图片经本项目服务器发送给所选模型。

动作目录保留 32 个名称、类别与教学入口，其中 25 项有现有 3D 演示。目录只用于名称和演示匹配，不包含姿态标准、权重、角度阈值或器械识别规则；AI 可以识别目录外动作。

可靠的视觉名称需要至少两个实际发送的图片时间及具体文字依据。填写目录 ID 时，ID、名称和类别必须一致。没有充分证据时保留未知或候选；纯文本模型不能凭坐标伪装成视觉确认。动作名称确认与是否标准分别处理。

## 结论与纠正建议

模型输出的 `verdict` 包含 `status` 和一句 `summary`。`feedback` 说明观察到的问题或优点、证据时间与可执行建议。软件检查这些引用真实存在，不用固定动作规则替 AI 判断。

- 确认“基本标准”需要模型明确作出这一结论，有可观察的良好动作证据，且没有实际问题、未决反馈或严重数据缺失。
- 有可靠的局部问题时可以提出纠正建议，即使其他片段看不清，也要说明局限。
- 数据未完整审阅、动作未确认或观察不足时，不能强行二选一。
- 缺失、遮挡或低置信度表示证据不足，不表示动作本身有错误。
- 模型不能生成数字评分，也不能把没有发现问题当作已经证明动作标准。

33 个姿态点没有完整胸腰椎测点，无法直接测量脊柱曲线。关键图片可以提供可见外形，但同样不能证明真实腰椎三维位置；单目估计的世界坐标不等于测得的人体结构。足底受力、实际肌肉发力与遮挡部位不能凭空推断。完整数据传输和引用校验也不等于模型解释一定正确，评价质量仍需真人视频与独立标注验证。

## 保存与版本升级

新报告使用 `motion-report-v1`，只保存：

- AI 确认的动作名称、目录 ID、类别与识别依据。
- 结论、最多 3 条展示建议及其时间、帧编号或测量路径引用。
- 数据质量摘要、完整审阅数量、模型信息与耗时。
- 视频名称、尺寸、时长和创建时间等元信息。

原视频、临时图片、完整骨架、逐帧测量、分数和姿态规则结果均不写入新报告。保存不会自动完成训练。报告可跨设备同步，单份上限 1 MiB；关闭页面后历史报告仍可阅读，但回放需要重新选择原视频。

已有历史记录不迁移、不重写，仍可在简化界面中阅读。旧版存在且有证据的视觉问题可继续展示，旧分数不会被转换为“动作标准”的结论。

**更新后必须刷新页面并重新分析视频。** `POST /api/motion/coach` 只接受完整 `poseData` 与新版客观测量 `fullAnalysis`，不再支持仅有旧评分摘要的请求。旧请求会提示刷新，不会继续执行旧评价流程。JSON 最终响应和 SSE 进度响应仍可使用，差别只在返回方式。

| `server/motion-coach.mjs` | 完整请求校验和统一调用入口 |

| `tests/motion-*.test.mjs` | 数据完整性、测量、证据引用、API、报告与页面回归 |

使用原有 Node 服务启动，无需额外 Python 服务。静态模型资产约 32 MB，视频兼容组件另约 32 MB，均按需加载并由 Service Worker 缓存。部署时同步更新应用模块、Worker、WASM、模型与缓存版本。

完整请求上限为 24 MiB，其中骨架不超过 16 MiB、客观测量不超过 2 MiB，最多 1,800 个采样帧。测量行数、下标和时间必须与骨架一致。最多 6 张 JPEG／PNG 图片，每张不超过 512 KiB、长边不超过 1280，总计不超过 2 MiB；浏览器默认长边 640。超过限制会明确提示，不截去后半段数据。

服务端仅使用当前账号的动作点评模型配置，校验请求、图片尺寸和证据引用。模型没有工具权限，不能修改训练或健康记录。原始骨架、图片和中间批次只用于本次请求，不持久化。

服务器需提供正确的 JavaScript、WASM 与 `.task` MIME，CSP 允许同源 Worker、WASM 编译及 `blob:` 视频。本项目已配置。

## 验证方法与已有边界

运行本地检查：

~~~powershell
npm test
npm run check
npm run motion:assets
~~~

`motion:assets` 仅校验固定资源的散列。缺少模型文件时运行 `node scripts/setup-motion-assets.mjs`；缺少视频兼容组件时运行 `node scripts/setup-motion-codec.mjs`，从固定来源恢复。

当前版本验证（2026-10-04）：468 项自动化测试、语法检查与资源散列校验通过；AI 流程的 47 项浏览器检查通过，覆盖完整数据发送、无评分字段、流式进度、超时重试、取消、保存、历史和手机布局。真实 GPU 视频验证完整提取深蹲 168 帧、俯卧撑 267 帧，并生成一一对应的客观测量；此前简化流程的 6 个目标跟踪场景与 30 份缓存骨架回放也通过。删除了旧评分功能对应的测试，新增和改写了客观测量、完整传输及简化报告测试，数量不能直接与旧版比较。

视频解码专项运行 `node scripts/qa-motion-codec.mjs`，覆盖原片首帧、完整骨架、6 张关键图片、采样回放、格式与尾帧、取消及资源释放，并记录是否存在整段视频重编码。浏览器验证使用桌面 Edge，尚未在各款 iPhone、Android 真机浏览器验证。

直接解码专项通过 16 种扩展名、19 种配置。原 HEVC/HLG MOV 保留 1920 × 1080 显示尺寸和 13.003333 秒时长，得到完整 196 条骨架采样、196 行观测、66 张回放 JPEG 与 6 张 AI 证据图片；未发现中间 H.264 编码、原视频上传或外部资源请求。当前本机测试首帧准备 0.54 秒，骨架分析 61.92 秒，关键图片提取 7.19 秒，整链 69.79 秒（不含 AI 调用），对比上一版 147.85 秒耗时减少约 53%。此片默认跟踪有 30 行有效测量，其余保留未知；完整解码不代表所有骨架均可靠。完整记录见 `.qa/motion-codec-WHhl5h/results.json`。

时长边界运行 `npm run qa:motion:decode-boundaries`，无需 GPU 或用户视频。5 项检查覆盖 0.01 秒单帧、2.01 秒分数时长、低帧率，以及声明时长过短、过长的拒绝处理。以整数采样数量保留最后有效采样点，同时检查实际源画面时间；不会用不完整骨架返回成功。

浏览器测试使用隔离账号、临时数据库和受控 AI 上游。设置 `QA_PLAYWRIGHT` 与 `QA_BROWSER` 后运行对应脚本，例如 `node scripts/qa-motion-coach.mjs`。测试产物在 `.qa/`，不读取用户模型密钥，也不能证明用户实际供应商的响应速度或建议质量。此次未调用真实 AI 服务；真实视频验证使用本机 MediaPipe，离线专项分支此次未运行。

以下来自评分流程及完整数据初版，保留为素材与已知问题记录，不作为当前 AI 评价准确率或当前测试数量：

- 上一版先生成兼容 MP4 的路径通过 16 种扩展名、19 种配置。用户 iPhone HEVC/HLG MOV 的转换、195 帧骨架与 6 张关键图片合计约 148 秒；记录为 `.qa/motion-codec-bnAZIL/results.json`。该路径现已替换为原片直接解码，这个耗时仅供历史比较。
- 曾用真实 MediaPipe、关键画面和当时配置的模型测试俯卧撑、普通引体、杠铃卧推、高位下拉与坐姿绳索划船。卧推、划船的目标覆盖率分别约 27.2% 和 43.4%，提示卧姿、遮挡和器械场景仍需改进。
- 多人样例验证过中央选择、手动点选、目标离场及自然健身房场景。拼接视频仅用于跟踪功能验证，不代表真实人物交叉的全部情况。
- 公开视频与数值 fixture 用于解码、跟踪、数据完整性及回归。来源见 `scripts/motion-sample-sources.json` 和 `tests/fixtures/motion-video-sources.json`；它们没有完整的教练逐项标注。
- 旧评分流程出现过公开数据标为 bad 的深蹲仍获得高分。该流程现已移除，但不能反过来证明新 AI 能正确识别该样例，需要重新实测。
- 旧版“490 项自动化测试、40 项浏览器检查”等结果属于此前实现，不能当作本版通过数量。

下一步用教练独立标注的视频验证动作名称、问题的误报和漏报、建议可执行性及“无法判断”的比例。按人物隔离验证数据，避免把同一人的相似视频同时用于调整和验收。
