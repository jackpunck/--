# 3D 动作接入

主应用将 `精细模型与动作开发/` 中的页面、样式、打包文件及许可文件映射到同源 `/model/` 路径。

## 打开已有动作

```html
<iframe
  src="/model/index.html?exercise=pushup&embed=1"
  title="俯卧撑 3D 动作演示"
  style="width:100%;height:80dvh;border:0"
></iframe>
```

| 动作 ID | 动作名称 | 主要肌群 |
| --- | --- | --- |
| `squat` | 徒手深蹲 | 股四头肌、臀大肌 |
| `pushup` | 俯卧撑 | 胸大肌、肱三头肌 |
| `curl` | 哑铃弯举 | 肱二头肌 |

以上是三个示例 ID。当前 25 个动作均提供教学演示和相对发力颜色，其中 24 个为往复动作，`plank` 为持续等长支撑，姿态和用力颜色保持稳定。完整 ID 列表见 `public/domain.js` 和模型 `exercise-catalog.js`。缺省动作是徒手深蹲；显式传入未知动作时显示不支持，不能悄悄回到深蹲。

`embed=1` 隐藏独立页面的品牌栏和开场介绍，隐藏独立页的动作快捷入口、动作目录和动作/解剖模式切换，仅展示传入目标；保留播放／暂停、0.5 倍／0.25 倍慢放、进度拖动、旋转、缩放、四个视角、观察范围、材质、肌肉高亮、解剖观察、肌肉名称与动作要领。窄屏改为上下布局，页面可滚动。独立打开时省略 `embed` 即可。

## 肌肉图谱与紧凑卡片

```html
<!-- 主要肌群高亮，支持点选模型表面的肌肉名称 -->
<iframe src="/model/index.html?mode=atlas&muscle=biceps&embed=1&compact=1" title="肱二头肌 3D"></iframe>
<!-- 独立左侧结构；通过 URLSearchParams 编码原始 mesh 名称 -->
<iframe src="/model/index.html?mode=atlas&structure=Serratus%20anterior%20muscle.l&embed=1" title="前锯肌（左侧）"></iframe>
```

`muscle` 支持 chest、biceps、triceps、deltoids、lats、traps、core、obliques、quads、hamstrings、glutes、calves、forearms。`structure` 必须是模型 manifest 中真实存在的肌肉名称。主要肌群高亮可包含多个解剖结构；单结构标题标明侧别，并标注“透视高亮”，使深层肌肉也可见；表面点击仍使用真实几何拾取。

`compact=1` 适配对话内的窄卡片；完整图谱保留旋转、缩放、名称与点选功能。界面用真实网格渲染，不向外部图片服务请求人体图片。

同源父窗口还可发送 `{type:'fitness:muscle',muscle:'lats'}` 或 `{type:'fitness:structure',structure:'Serratus anterior muscle.l'}`。选择后发送 `{type:'fitness:muscle-selected',muscle,name,structure}`；直接点击表面也发送这个事件。接收方必须校验 `event.origin` 与 `event.source`。

## 在已打开的 iframe 中切换

可直接更新 `iframe.src`，或使用同源消息避免重新加载模型：

```js
const frame = document.querySelector('iframe');
frame.contentWindow.postMessage(
  { type: 'fitness:exercise', exercise: 'curl' },
  window.location.origin,
);

window.addEventListener('message', event => {
  if (event.origin !== window.location.origin || event.source !== frame.contentWindow) return;
  if (event.data?.type === 'fitness:ready') {
    // { type, exercise, title, webgl }
    // webgl=false 时仍可阅读及切换文字指南。
  }
  if (event.data?.type === 'fitness:selected') {
    // { type, exercise, title }；初始选择、页内切换及消息切换都会通知。
    frame.title = `${event.data.title} 3D 动作演示`;
  }
});
```

父页面应在创建 iframe 前注册监听，或使用 iframe 的 `load` 事件发送切换消息。`fitness:ready` 在初始化结束后发送；发送到 iframe 的消息必须来自它的直接父窗口且严格同源，未知动作和消息类型会被忽略。直接以 `file://` 打开仍可使用页面，但不提供消息桥接。外部切换会回到动作模式，将进度重置为起点。

## 修改与验证

在 `精细模型与动作开发/` 中运行：

```sh
npm ci
npm test
npm run build
```

构建后，网页入口 `demo.bundle.js` 包含 Three.js 和消息接口，网格由 `atlas.worker.js` 读取 `assets/anatomy-data.bin` 后解码；`demo.offline.js` 保留全部内嵌资产供双击打开。网格与骨架检查继续执行，并验证新旧解码结果一致。新增动作后在根目录执行 `npm run sync:models` 更新共享能力清单，其他步骤见 `精细模型与动作开发/新增动作指南.md`。

## 署名与模型范围

嵌入模式保留页面底部的 Z-Anatomy / BodyParts3D 署名、CC BY-SA 4.0 链接及完整许可文件链接。发布时须保留 `THIRD_PARTY_LICENSES.txt` 和模型源文件的许可说明。模型采用教学骨架和近似蒙皮，高亮用于说明目标肌群，并非实测发力强度。

主服务对模型资源使用 `Cache-Control: no-cache`，浏览器每次验证 ETag；未变化时返回304。文本静态资源支持 gzip，已压缩的网格二进制直接传输。入口版本见 `index.html` 和 `model-loader.js`；二进制请求带资产内容摘要，避免旧缓存与新元数据混用。

## 详情窗口复用与绘制控制

主应用通过 `public/model-viewer.js` 维护独立的 `#model-dialog`。首次传入正确目标URL建立iframe；后续不改 `src`，通过上述同源消息切换动作、肌群或单个结构。快速连续选择时，等待最新请求对应的实际绘制回执后再揭示画面，避免名称已切换但画面仍停留在上一部位。

父窗口关闭时发送 `{type:'fitness:visibility',visible:false}`，重新打开时发送 `visible:true`。查看器检查直接父窗口、同源和boolean参数；关闭、页面隐藏或离开可见区域时取消渲染循环。肌肉图谱与暂停的动作仅在变化时绘制，动画在播放时继续逐帧绘制。

`fitness:ready` 在首帧绘制后发出，包含 `webgl`、`mode`、`exercise`、`muscle`、`structure`，允许父窗口确认首次目标已显示。动作和肌肉选择回执也携带 `mode`，父窗口同时核对对象与模式。实际选择事件会使父窗口失效旧选择缓存，避免用户在模型内点别处后再次打开原目标时误用旧状态。

父页面切换目标及恢复可见性时附带非负安全整数`requestId`。选择回执只说明状态已更新；`fitness:rendered`在标签更新及真实WebGL绘制完成后返回当前目标、模式和请求ID。父页面仅在回执与最新请求都匹配时撤下加载遮罩，快速A→B→A也不会接受A的旧回执。动画连续播放不会每帧发送该回执。

图谱模式按未变形的实际网格进行表面拾取，动作模式继续按蒙皮后网格拾取。两者均保留triangle到真实解剖结构的映射。单结构高亮复用原批次的GPU属性缓冲，不在每次选择后释放共享缓冲。

肌肉图谱名称与位置的核对、透视高亮及拾取规则见[肌肉图谱核对](肌肉图谱核对.md)。
