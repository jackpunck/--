# 方案库实施计划

**目标：** 将已批准的方案库设计实现为日历上方的小弹窗。保留日历页面及滚动位置，支持多份草案、自动编号、自定义名称、编辑和循环导入。

**结构：** `public/plan-library.js` 负责编号、旧数据迁移和导入校验；`public/app.js` 接入现有 RecordStore、dialog 和循环排期；`public/app.css` 提供与项目一致的紧凑弹窗样式。保存方案不修改日历，导入时一起保存活动计划、循环规则及日程快照。

- [x] 先写 `tests/plan-library.test.mjs`，验证多方案编号、改名/删除后序号递增、旧模板及草案迁移幂等、模板与日程快照隔离、无效方案不能导入。
- [x] 实现独立方案记录与持久序号。旧活动计划保留原名收进库内；导入过的库内方案不重复迁移。重置日历不清空方案。
- [x] 日历下方只保留右对齐的「方案库」按钮和数量；弹窗内部列表滚动，页脚保留开始日期及「循环导入日历」。新增方案生成后保存并打开方案库，名称按方案一、方案二递增。
- [x] 将现有动作编辑器绑定到选中的方案记录，保存后返回方案库。改名、删除与导入校验当前记录，防止覆盖同步后的改动。
- [x] 导入保留历史与已完成训练，替换所选开始日期起旧循环的未完成安排，遵循繁忙日规则；重复导入同一版本和日期不重复排期。
- [x] 更新资源缓存，运行语法检查及完整测试。在隔离浏览器检查弹窗、创建多份、编辑改名、导入、刷新、删除、手机布局和旧数据迁移。

- `npm.cmd run check` 通过；`npm.cmd test`：169 项通过。
- 隔离 Edge 验证方案创建、改名、增删动作、循环导入与重复导入、繁忙日避让、刷新保留、删除后递增命名、日历重置保留模板，以及旧模板和草案的幂等迁移。
- 已核对桌面 620px 弹窗与手机内部滚动；背景日历保留，关闭后滚动位置不变。
