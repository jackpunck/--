# 算法与资料来源

本应用中的训练与饮食结果是可修改的估算草案。领域模块位于 `public/domain.js`，无联网、存储或确认副作用。确认计划、确认餐食以及同步由应用层处理。内置资料尚未经过独立临床或教练审核，界面和 AI 不应称其为“已审核知识库”。

原表存在性别限定、排除食物以及高组数等建议，本应用没有把这些文字全部转为强制规则。二分化（全身A/B）、标准四分化（上/下肢A/B）与五分化是应用扩展，并在生成结果中标明。休息日是应用插入的初始安排，用户可另排日期。

## 公开资料查证

查证日期：2026-09-28。

- **静息代谢**：[Mifflin 等原始研究，1990](https://pubmed.ncbi.nlm.nih.gov/2305711/)给出男女方程以及简化式。这里估算的是静息能量消耗，界面使用常见简称“基础代谢”；不是间接测热实测值。
- **营养结构**：[NIH ODS 运动与运动表现资料](https://ods.od.nih.gov/factsheets/ExerciseAndAthleticPerformance-HealthProfessional/)列出运动人群蛋白质约1.2–2.0g/kg与脂肪约20%–35%能量。应用取1.6g/kg（减脂1.8g/kg），并以30%能量限制蛋白质，脂肪取28%，剩余给碳水。这些具体默认值是应用选择，不能理解为NIH对这个应用或个体方案的认证。
- **适用人群**：[NIDDK Body Weight Planner](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner)说明成人用途，并排除孕哺等情形。应用自动目标限18–100岁；BMI低于18.5不生成减重目标。1200kcal是本应用避免很低自动结果的保守下限，不是人人适合的摄入目标。医疗营养需求应由专业人员个体制定。
- **训练原则**：[ACSM 2026更新](https://acsm.org/resistance-training-guidelines-update-2026/)强调规律训练、覆盖主要肌群、个体化；徒手和居家训练也有效。不根据用户性别跳过胸、股四头肌或核心，不要求训练到完全力竭。具体模板仍需结合周历、经验和恢复调整，模板不是ACSM原版处方。
- **动作资料**：[NASM动作库](https://www.nasm.org/workout-exercise-guidance)用于核对动作名称与肌群，中文要领由应用整理；[ACE徒手深蹲](https://www.acefitness.org/resources/everyone/exercise-library/135/bodyweight-squat/)与[NASM俯卧撑](https://www.nasm.org/resource-center/exercise-library/push-up)用于查证这两个动作的主要要领。现有连续动画为深蹲、俯卧撑、哑铃弯举；另外22个目录动作提供静态3D姿态并标明类型。
- **食物数据的边界**：[USDA数据说明](https://fdc.nal.usda.gov/data-documentation/)区分实验分析、膳食调查和品牌标签数据。本版本没有导入完整USDA数据库，不把种子估值声称为USDA逐项检测结果。包装营养标签优先，混合餐、烹饪失水和用油会影响结果。

## 计算口径

### 营养目标

身高单位cm、体重kg、年龄整岁、能量kcal、三大营养素g。内部计算保留精度，展示时能量取整数、营养素取1位小数。舍入后4×蛋白质+4×碳水+9×脂肪可能与总能量相差不足1kcal。能量4/4/9是近似方法，未单独计膳食纤维、糖醇、有机酸和酒精。

活动系数与额外训练热量是初始假设，没有读取穿戴设备或实际训练消耗。15%缺口、5%盈余、1200kcal下限均需结合记录理解，不自动根据短期体重波动更改固定训练计划。

前端首次建档会明确保存`activity=1.375`（轻度日常活动），以后打开阶段编辑时保留该值。单独调用领域函数且省略`activity`时，使用参考Excel的1/0.7回退值。结果说明会列出实际采用的系数。

### 记餐和替换

`sumFoods([{ foodId, grams, kcal?, protein?, carbs?, fat? }])` 将每100g营养乘以份量/100后汇总。显式传入的0保留。自定义食物没有库中ID时必须传入完整四项每100g营养，缺失、负数和非有限数均报错。

`substituteFood(foodId, grams, replacementId, basis)` 按能量/蛋白/碳水/脂肪中的一项等量计算替代份量，同时返回替换前后总量及全部差额。按一项等量不表示其他项相同。

`convertFoodWeight(grams, rawBatchGrams, cookedBatchGrams, direction)` 使用用户实测整批生重/熟重比例。没有硬编码“生米固定变成几倍熟饭”；油糖等另计，默认混合均匀。

### 训练与力量

`generatePlan({split,variant}, profile)` 只返回草案。`days`是循环中的训练与休息顺序，不是固定周一至周日，也不是每周次数承诺。新手可减至每动作1–2组。时间单位秒，平板支撑以秒计。

`estimate1RM(weight,reps)` 返回Epley、Brzycki及两者最小/最大值。Epley=w×(1+r/30)，Brzycki使用Excel系数。重复次数为1时直接显示已完成的重量。两公式差值不是置信区间，也不是对尝试极限重量的许可。

### 食谱

`suggestRecipe({profile,days,meal,preferences,restrictions,trainingTime})` 返回：

```js
{
  title, target, source, notes,
  days: [{
    day,
    meals: [{key, name, items: [{foodId, name, grams, state}], totals, energyShare, timing, preparation}],
    totals,
    difference // 相对该餐/全日目标的四项营养差额
  }]
}
```

天数1–7；餐次为`day/breakfast/lunch/dinner/snack`。默认早/午/晚/加餐能量占比25%/35%/30%/10%。能识别的训练时间（HH:mm或早/午/晚）会把全天10%能量从另一正餐移到训练附近的正餐，全天总量不变；这是便利性的应用规则，不是营养时机疗效承诺。

本地食谱按能量预算、可用食物和可识别限制生成，属于规则配餐，不能冒称调用了AI。支持常见食物/过敏原排除和素食偏好，但不是完整过敏原或疾病营养系统。宏量营养目标可能不完全匹配，返回实际计算总量与差额。未自动记账。

## 自动检查

运行 `node --test tests/domain.test.mjs`。测试独立代谢算例、能量守恒、参数边界、不可用变式、循环休息、所有动作引用、三种真实演示、食物汇总及零覆盖、1RM、营养替换、生熟换算、单餐/多日和饮食限制。测试不验证个体临床效果。

### 知识大全中的独立试算

`knowledge-tools.js` 的静息代谢与上述Mifflin公式一致，全天消耗只乘活动系数，不叠加训练额外热量；它与用于每日营养目标的规则是两个用途。计算器不修改档案或目标。宏量营养素热量采用4/4/9，参考 [FDA 食品标签指南](https://www.fda.gov/files/food/published/Food-Labeling-Guide-(PDF).pdf)。

12种常见份量复用应用原有食物库，容器重量是可调整示例。具体假设与结果见 [知识大全](知识大全.md)。
